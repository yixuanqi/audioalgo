# 连线编辑与节点库分类测试及通过准则

## 1. 通过语义

配套[修改方案](plan_connection_editing_and_node_library.md)与[TDD执行规程](agent_loop_connection_editing_and_node_library.md)。本文件仅定义待实施契约，**没有新增测试已注册/执行/通过的声明**。NCE-01～10、NLC-01～08、NRG-01～04均各含a/b/c，共66个必需子项，不替代原NED/AR/G/UPN/NA/PC/NWS。

每子项单列状态passed/failed/not_run/not_verified/blocked/skipped/timeout，只有passed计通过。父项须三个子项全部通过；缺注册、零收集、只存在控件、跳过、退出码错误、缺独立产物或桌面证据都不能passed。允许一个真实测试覆盖多个子项，但每项映射精确用例名及具体断言/产物，不能只映射父标签或用字符串扫描代替行为验证。

层次：P=pure模型/Controller；C=真实生产JUCE组件及事件；I=实际插件进程/SDK/文件/GUI组件运行与CLI产物；D=允许工具操作真实OS窗口；F=证据基础设施。P/C/I不能冒充D。表中“+”为全部必需；D暂停时自动化子集可交付，正式专项仍未通过。浏览样式不做颜色/像素快照镜像测试，命中、可达性和行为必须验证。

## 2. 独立fixture与判定基准

- 自有临时工程：A→B→C的线性链；A→B及A→D的分支；空闲同型节点；Mixer双输入；不同类型/方向/缺端口/环候选；重叠与负坐标节点。编辑层分支fixture不代表新增运行拓扑支持。
- 全状态快照至少含project ID/epoch/revision、节点及顺序、边四元组及顺序、参数/资源/布局、selected output/port、包精确锁、dirty及undo/redo大小。只比较节点/边数量不足以判断取消或无回退。
- 位移使用UI逻辑px：5、6、7验证>6起拖；边距离7、8、9验证<=8命中；共享坐标变换，覆盖缩放0.5/1/2（若当前合法范围更窄先记录契约并覆盖合法端点）、平移和负模型坐标。不得复制产品命中函数作为期望。
- 浏览fixture独立列出固定分类、排序与查询期望，含中文/emoji、同名不同type_id、标签、多用途、旧无browser节点、未知/损坏browser及边界32/33 tags、64/65字节tag、2048/2049字节描述。未知浏览数据降级与非法执行描述拒绝分别测试。
- 包fixture：旧ABI v1 DLL无browser、新带browser且内外manifest一致DLL、仅外部manifest被改的反例；外部Python、单文件作者、目录作者各有带/不带browser版本。旧冻结NWS/原生SDK fixture及golden不改；新fixture放独立目录，记录精确字节hash。
- 音频使用既有可复用F01/F02解析信号，至少48000Hz双通道513帧、互异非零通道，host127；增益用float64的`x*pow(10,gain_db/20)`，通道交换用独立索引映射。每样本`abs(actual-expected)<=2e-6+1e-5*abs(expected)`；采样率、帧数、通道顺序、有效区间精确一致。若既有用例更严，保留其阈值。GUI组件和CLI分别与独立oracle比较，不能只互相比。
- 一个明确混合Python/C++链复用当前有效作者闭环夹具和独立公式；记录实际helper/source/package hash。分类前后同一锁定算法/参数应满足同一oracle；分类引起新包hash属正常新版本，不要求新旧包hash相同。未改的旧包字节hash和旧工程输出保持。
- 不覆盖用户音频、截图中的PrintA、用户编辑器/设置文件或安装目录；自有fixture按生产命令进入系统。
