# 自定义节点开发方式评估与实施方案（提案，尚未实现）

2026-10-26。此文是选型概览；具体接口、阶段和依赖见[详细开发方案](plan_node_workspace_implementation.md)，逐项通过准则见[验收方案](testing_node_workspace_authoring.md)。它不改变已经通过的单文件 `.aadraft` 契约，也不把拟议功能计为已交付。实施仍按[唯一当前摘要](development_status.md)与 NA/PC 验收推进。

## 诊断与结论

当前工作台将完整节点声明 JSON、单个源码字符串和日志同时铺在一个面板。小型算法可以快速试验；一旦出现辅助模块、测试或 C++ 头文件，就没有明确的项目边界。截图所示卷根 Save As 失败是独立缺陷：已存在的 `D:\` 被再次要求创建，修复与多文件改造分开验收。

先确定节点工程的数据模型，再选择编辑器。要解决的核心不是换一个文本框，而是多文件、依赖、调试、错误定位、保存冲突与版本复现。AudioAlgo 应负责节点契约、环境识别、受控 Check/试跑、版本 Apply、节点库与运行身份；代码编辑体验可以有多种实现。**以下选择是技术建议，并非用户已确认 VS Code 的角色。**

参考依据：GNU Radio 的 [OOT 模块教程](https://wiki.gnuradio.org/index.php?title=Creating_Python_OOT_with_gr-modtool)把节点源码与图形描述放在宿主源码外；Node-RED 的[节点打包文档](https://nodered.org/docs/creating-nodes/packaging)将包声明、运行代码和编辑端分开；Godot 同时提供[功能完整的内置脚本编辑器](https://docs.godotengine.org/en/stable/tutorials/editor/script_editor.html)及[外部编辑器集成](https://docs.godotengine.org/en/latest/tutorials/editor/external_editor.html)，包括外部修改重新加载和错误行定位。这些是设计参照，不代表它们的包格式可直接套用到 AudioAlgo。

## 编辑方式比较与建议

| 方式 | 用户体验 | 代价/风险 | 对本项目的判断 |
| --- | --- | --- | --- |
| A. 扩展现有 JUCE 面板为完整 IDE | 单窗口完成多文件、查找、补全、调试 | 需要自建文件树、语言服务、构建诊断、调试器及一致性处理；Python/C++ 双语言持续维护成本高 | 不适合作为第一步；保留小节点快速编辑与声明表单 |
| B. 嵌入 Monaco/WebView 等第三方代码控件 | 单窗口代码体验可明显改善 | 要维护 JUCE↔WebView 消息、文件系统和焦点/快捷键/无障碍/DPI；Monaco 本身不提供完整 Python/C++ 构建调试环境 | 可以在节点工程及检查协议稳定后评估，不先引入 |
| C. 以外部 IDE 编辑真实文件夹，AudioAlgo 管理节点生命周期 | 多文件、Git、搜索、Python/C++ 补全和调试沿用成熟工具；节点 Check/Apply 仍在应用内 | 用户需切换窗口；须做好磁盘监听、冲突、诊断跳转和统一命令 | **建议作为多文件专业开发的首选路径**，先支持任意外部编辑器，再优化 VS Code/Visual Studio 集成 |

因此建议采用“节点工程目录 + 专业编辑器 + AudioAlgo 验证/应用”作为复杂节点的主路径。VS Code 是首个适配的编辑器候选，**不是已经选定的唯一编辑器，也不是运行节点的必装依赖**；C++ 用户可能更适合 Visual Studio。现有内置面板继续支持简单单文件试验，但不要把它发展成必须覆盖完整 IDE 功能的核心路径。若后续实际用户验证显示频繁切换窗口明显妨碍工作，再以稳定的文件夹契约评估嵌入 Monaco 或做更完整的内置编辑器。

## 文件夹契约

单文件草稿继续可 Save/Open/Recover/Apply。新建“节点工程”或从 `.aadraft` 显式转换时，创建一个目录；转换先完成新目录和校验，成功后才改变编辑绑定，不覆盖旧草稿。一个目录只有一个权威 `node.json` 声明及源码树；不同时将 `.aadraft` 内嵌源码当作第二份权威。已安装版本只读，修改需复制成新草稿/工程。

下面是**目标示例，非当前可直接导入格式**；实际字段沿用既有 SDK manifest，经版本化 schema/fixture 落定。

```text
PrintA/
  node.json                 # type_id、语言、版本、端口/参数、入口点
  src/print_a/__init__.py
  src/print_a/process.py   # process(inputs, params, state)
  src/print_a/filter.py    # 可由 process.py 导入的辅助代码
  tests/test_process.py
  requirements.lock        # 可选：可复现依赖记录，不触发自动安装
```

```text
MyFilter/
  node.json
  include/my_filter/filter.h
  src/filter.cpp
  src/node.cpp              # 用户算法入口；薄 ABI 适配在 staging 生成
  tests/filter_test.cpp
```

Python 入口点用明确的相对模块/函数定位，例如 `print_a.process:process`；runner 仅从本次冻结快照的源码根解析受管模块，不依赖用户电脑上的同名包或宿主进程 `sys.path`。C++ 基础模式从显式源码清单在冻结 staging 中生成构建文件，仅消费发布的 Node SDK，独立编译 DLL；任意用户 CMake 脚本不自动作为工作台构建命令执行，可在高级外部 SDK 工作流中另行使用。包内声明与 DLL 描述必须一致；部署新版本后重启现有宿主，不要求重新编译宿主，也不承诺运行时热卸载。用户算法分文件、单元测试和构建依赖属于节点工程，不能借此修改通用画布/调度器的算法分支。

文件收集使用明确白名单与限制（现有计划的 Python ≤128 文件/8 MiB 作为起点）；拒绝 `..`、绝对路径、逃出根目录的链接、重复规范化路径及未声明的执行依赖。环境身份包含解释器/依赖锁或 SDK/编译工具链；不在 UI 线程、设备回调中加载或执行用户代码，不静默联网/安装依赖。进程隔离用于稳定性和限时，不能宣传为完整安全沙箱。

## 编辑与验证交互

```text
节点名称 / 工程路径 / 文件状态                    [打开代码工程] [检查/试跑] [应用]
节点文件与诊断   │ 当前文件/检查结果摘要（主要区域）    │ 端口/参数表单
                │ 打开源文件 / 跳转错误位置            │ 高级 JSON 折叠
──────────────────────── 可拖动分隔线 ────────────────────────
问题 / 检查输出 / 运行日志（有内容或失败时展开，平时收起）
```

专业模式下，代码以磁盘文件为准，AudioAlgo 不再保留第二份待保存的源码缓冲；旧内置快速编辑模式才有内存缓冲。表单是节点声明的唯一编辑权威，导入已有 manifest 先解析到表单；高级 JSON 如需开放手工编辑，必须与表单二选一并显示切换/冲突诊断，不能双向静默改写。保存写到用户目录；检查冻结所有纳入的源码和声明并计算整树 hash；Ready 绑定 generation、树 hash 与环境身份；Apply 只接受相同快照，原子安装不可变版本。磁盘外部变更或内置缓冲区变更立即使旧 Ready 失效，运行中的旧版本保持原快照。任何外部修改与未保存缓冲区冲突时提供比较/重新载入/另存，原字节先保留。

“打开代码工程”调用用户配置的编辑器，以参数数组传入目录/文件/行；首个适配器可用 VS Code 的[命令行](https://code.visualstudio.com/docs/configure/command-line)，第二个适配 Visual Studio 或系统默认编辑器，不拼接 shell 命令。检查入口始终在 AudioAlgo 内；可额外导出 VS Code [tasks.json](https://code.visualstudio.com/docs/debugtest/tasks) 或其他 IDE 的任务模板，调用相同检查命令。不能把外部进程退出当保存信号；监控文件变化后重新读 hash，检查前显式确认内容。编辑器配置不是节点包运行所必需，也不打包到最终不可变版本。

## 实施顺序和退出条件

1. **保存可靠性与状态**：卷根/UNC 已存在父目录直接复用，真实 Save As 到卷根和普通目录分别验收；失败显示路径、具体操作与可恢复建议，不能显示“已保存”。当前卷根代码修复已有自动化证据，真实桌面选择器和目标卷写入权限仍需验证。
2. **单文件工作台减负**：保留源码快速编辑；声明改为端口/参数表单，折叠高级 JSON/空日志，提供诊断定位和明确 Save/Check/Apply 状态。不要在这里提前制作完整 IDE。保留 `.aadraft` 恢复、冲突及现有节点身份。真实组件与桌面证据分开记录。
3. **目录格式与迁移**：先定 schema、合法文件路径、入口点、资源和依赖契约，再实现 `.aadraft` 无损转换、目录原子保存/恢复及外部改动检测。用两个 Python 源文件演示辅助模块参与数值计算；测试改动辅助文件会使旧 Ready/版本 hash 失效，旧安装版本仍按旧结果运行。
4. **统一检查/打包**：GUI/CLI 同一目录快照、受控 runner、错误文件/行、限额、取消、不可变包与工程精确版本锁；构建/执行不得读取正在变化的工作目录。C++ 同一发布 SDK 独立构建/probe 后待重启激活。
5. **专业编辑路径**：外部 IDE 打开工程、诊断跳转、磁盘变更/冲突处理和任务模板；验证 VS Code、Visual Studio/通用编辑器、无预设编辑器时的完整 Check/Apply/画布 Run。根据实际可用性再决定是否投资嵌入式代码控件。最终再做真实桌面、DPI、重启和 Release 累计验收。

每一片沿用 Red→Green→直接受影响回归→证据与唯一状态摘要的规程。不得将阶段 1 的保存修复或本文档视为阶段 2～5 已完成。
