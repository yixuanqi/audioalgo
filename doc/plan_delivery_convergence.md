本文中“当前不存在/尚未实现”等初始状态描述均指2026-10-22补充约束首次编写时。后续真实代码、已执行范围与剩余缺项以[唯一当前摘要](development_status.md)为准，已实现的SDK/包布局/命令见[原生SDK说明](native_node_sdk.md)；这项时间语义澄清不改变UPN、原累计验收或阈值。

本轮只更新文档与必要的验收文档hash绑定，没有实现DLL加载器、SDK、runner或新算法，也不宣称新增测试通过。下文的新接口、命令、目录与验收均为待实现契约。原110个AR字母子项不删改；新增UPN要求单列，最终交付须同时满足。

5. 一份原始命令记录、JUnit和产物可供多个需求引用，不为共享事实重复执行或复制长篇报告。采集、执行与登记走一个入口，避免命名模式不同导致真实构建记录不可发现；只修复本次涉及的问题，不先重写整个证据系统。
6. 测试、构建、暂停、权限、数据缺失分别记账。已知失败未修复前不宣称出口通过；外部验收缺失只阻挡相应完成声明，不阻挡独立功能开发。最终源码仍须一次完整Release累计回归及必需设备/桌面/质量/隔离安装验收。

## 5. C++用户节点独立编译与加载（新增必需范围）

### 用户流程与首版边界

用户在VS Code/Visual Studio等外部工具编写算法和薄适配，仅使用发布的Node SDK在独立工程构建DLL；将DLL、声明manifest及其依赖放入一个插件包目录；把该目录放入用户插件根或加入配置；重启编辑器/CLI后发现节点、生成参数和端口并执行。宿主EXE及通用画布/表单/调度器不得因新增插件重新编译、链接或增加算法分支。

保留内置静态节点及独立算法库。首版只要求启动时加载、更新后重启；运行中热替换/热卸载、任意C++编译器ABI兼容、完整原生崩溃隔离继续后置。每进程持有模块至实例和worker回收后退出；不在运行期间替换仍加载的DLL。

### 最小技术契约

- 发布可安装的Node SDK、版本化公共头文件、CMake包及一个外部插件模板。插件不依赖仓库源码绝对路径、JUCE/View或编辑器构建产物，不要求重新构建整个平台。
- DLL边界使用版本化C ABI：固定宽度字段、结构大小/ABI版本、opaque实例句柄、函数表及明确长度；不跨边界传递STL容器、JUCE对象、C++异常。具体导出名由实现片确定并记录，不把当前NodeRegistry的C++虚接口直接作为DLL ABI。
- 生命周期含创建、参数/格式prepare、process、reset、销毁及结构化错误；buffer借用与字符串/内存释放责任明确，实例在其创建模块销毁。公共能力与运行时准入相符，未支持的帧/端口能力定位拒绝。
- manifest声明插件ID/版本、SDK ABI、平台/架构、相对DLL路径和节点描述；加载前读取元数据，加载后核对API与描述。用户可配置插件根；启动发现顺序确定，重复ID、缺依赖、缺导出和ABI/架构不兼容有诊断且不留下半注册节点。进程内第三方访问冲突不在首版恢复保证内。
- GUI/CLI共用发现和注册装配，DLL处理器经桥接进入现有通用wrapper与RunService。只读catalog/自动表单不获得模块加载职责；计划/报告记录实际插件版本及DLL/manifest hash。
- 插件包的实际文件布局、搜索配置和CLI选项在实现时同时写入使用说明；上面的名称均为职责约定，当前不存在可宣称已可用的加载命令。

### 最小必需验收

以下各行的所有行为均必需；共享一份真实外部插件工程及运行产物即可，不为每行另建重复框架。初始状态全部`not_implemented/not_run`，不能以本次文档更新判passed。

| ID | 必须证明的行为 |
| --- | --- |
| UPN-01 | 从安装SDK在仓库外独立构建新插件，无源码树/JUCE/View依赖；宿主构建不参与，原EXE hash不变 |
| UPN-02 | 仅部署新插件包并配置搜索目录，启动GUI/CLI发现相同节点；端口/参数由描述生成，无通用产品源码修改 |
| UPN-03 | 参数控件经controller驱动实际DLL算法；GUI组件/CLI同工程各自符合独立数值oracle，报告含插件身份/hash；桌面证据另按原要求取得 |
| UPN-04 | 至少一组ABI不兼容/缺入口及重复ID或缺依赖负例明确拒绝、无半注册，内置Gain仍可运行；不承诺原生崩溃隔离 |
| UPN-05 | 两实例配置/状态隔离；关闭时先回收任务/实例再释放模块；只重新构建插件并重启宿主后新行为生效，EXE保持原hash且历史归属不串用 |
| UPN-06 | 干净受控目录仅有发布宿主、SDK/插件包及声明依赖，禁网完成外部构建/部署/运行；文档提供实际目录、构建与更新步骤及支持限制 |

实现P1时将UPN接入现有交付清单/执行入口并记录精确测试名、状态和证据；优先扩展现有工具，不另建平行Gate系统。当前AR/G验证器未收集UPN，单独退出0不足以证明新增插件要求通过。UPN不并入旧110个AR计数，也不替代EXT-01、AR-04/12或原桌面要求。
