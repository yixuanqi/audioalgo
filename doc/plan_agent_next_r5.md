### A1：完成已有 T25，双独立源贯通

涉及边界：RunService 资源捕获 → 纯计划源集合 → 后端源绑定 → sink → 产物/replay。接口名称由 Agent 根据已有代码决定，不能假定文中的目标接口已经存在。

实施要求：

- 每个输入按 `(node_id, port_id)` 或等价稳定身份绑定独立、已解码、不可变音频版本；在执行 prepare 前完成所需文件 I/O。禁止把同一个 AudioBuffer 复制给全部 source。
- NativePlan 使用元数据和源格式信息编译，不读取音频文件，不构造处理器；后端只消费计划及显式数据绑定。
- 保留旧单缓冲公开入口兼容性；多源调用旧入口必须返回明确的歧义诊断，不能猜测绑定。
- T25 首片显式拒绝不支持的采样率、帧数、通道 ID/布局、有效区间不匹配；定位到真实源/端口，发生在 block 工厂/prepare 前。当前没有对齐能力时不静默补齐/重采样；后续时序支持的范围由原验收决定。

Green 准则：

1. 两份互异双声道 WAV，513 帧，host=1/127/256，正常与交换接线共 6 组均逐样本符合 `2*A+3*B+frame/4096` 及 `2*B+3*A+frame/4096`；独立 oracle 不调用待测处理器/实现。
2. 保持两输入 hash/内容、左右通道和时间顺序；每实例每块一次执行，construction/prepare 次数正确。
3. 两份资源均入 manifest，hash 对应实际执行副本；replay 中每个源指向正确相对副本。对测试自有原件修改/删除后仍可重放，输出符合固定 oracle，不触碰用户原音频。
4. 增补格式/帧数/通道/区间负例，确认失败前工厂/prepare 计数为 0；不同资源和节点不会相互覆盖。
5. 保存真实 WAV、run/complete/replay 文件及独立读取验证报告。仅在测试 registry 有 mixer 时，明确该工程还不能由默认 CLI 消费。

### C：FIFO、消耗/产出、时延与尾部

队列是每项目最多一个执行+一个最新待执行；替换旧排队身份并有界保存对象。原生协作取消在块边界响应，受控 fixture 稳定时间≤5秒；关闭/New/Open/晚到回调无串用，50次编辑/运行/取消/重开检查无死锁及线性保留对象增长，心跳沿用 p95≤100ms/max≤500ms。不得强杀原生线程作为资源回收实现，也不把受控协作预算承诺给无响应第三方调用。

## 4. TDD 与验证节奏

本节的矩阵范围由2026-10-22[必要验证规则](plan_delivery_convergence.md#3-必要验证规则)细化：日常定向，稳定出口累计，先共享预检，再按影响扩大；原断言、容差和最终累计必需集合不变。

1. 每片只定义一个可验收行为及独立期望，记录影响模块、现有用例、必要 fixture、Red 原因和 Green 条件。已有真实 Red 直接引用，确认未漂移即可，不再次发明接口或复制同义测试。
2. Red 失败必须来自目标契约；编译失败、环境失败、产品断言失败分别记录。最小实现后同名同目标 Green，再重构和直接下游回归；不删断言、不改阈值/必需性、不生成同源 golden。
3. 日常使用 Debug 增量构建，正常一次只写一个构建目录；API/SDK变化补实际消费者和 Runtime OFF。仅对互不写同一目录的配置并行，避免同时启动多个相同目标构建。
4. 日常只跑目标与直接下游，稳定交付出口集中累计/构型验证，已有有效结果按影响复用。A0～A3已实施，不为恢复重跑；M21先关闭共享证据问题，禁止把同一产品快照在每个内部子片重新跑四构型。最终Release必需累计仍执行，新失败/影响扩大才扩测。
5. 昂贵 AR-05.d 隔离变异及安装消费者在受影响算法/边界或稳定阶段出口执行；无关 UI/helper/文档变化不每片重建三套副本。必需终验仍执行，隔离目录原子独占，不碰活动树或主 build。
6. 开始矩阵前固定产品源码/测试/验收清单，生成一次 manifest 并记录各构型环境、构建和 binary hash。矩阵期间不改参与验证的源文件。文档随后更新要列明差异、产品 hash 不变及复用范围，不能把旧总 hash 改写为新值。
7. 用实际执行的 testcase 统计 passed/failed/skip；Catch2 JUnit 的 tests 属性可能是断言数量。零测试/筛选只跑到旧二进制/缺少产物都不能通过；等待构建结束再验证 inventory 和执行。
8. Windows 沙箱进程若出现 0xC0000142，保留环境失败并按真实工具流程申请必要权限；不要复制同样命令无限重试。测试临时目录只使用项目专属可写路径，不删除外部用户目录；不导出完整环境变量或凭据。
9. 每片保存最小可重跑记录：命令、源码/构建/二进制 hash、Red/Green 原始结果、JUnit、独立 oracle、持久产物、剩余问题。无需为每条命令生成重复长篇分析。三轮同根因无进展就缩小复现、检查边界/假设并记录调整。
10. 每个行为结束更新状态顶部的“当前成果/实际失败/下一条”，历史记录不重写。持续推进下一片，常规阶段无需确认；不得擅自恢复桌面或自动提交。
