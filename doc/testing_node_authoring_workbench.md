# 自定义节点工作台测试与通过准则

## 1. 适用范围和通过语义

配套[开发方案](plan_node_authoring_workbench.md)与[TDD规程](agent_loop_node_authoring_workbench.md)。NA-01～17各含a～d，共**68个必需子项**。本次是验收契约，不表示测试已注册或执行；NA不并入旧110个AR计数，不替代G/NED/UPN。

结果分别为passed、failed、not_run、not_verified、blocked、skipped、timeout，只有passed计通过。一个父ID下全部字母通过才算该ID通过。缺注册/零收集/未执行/断言失败/跳过/超时/缺独立产物或桌面证据均阻止相应完成声明。开发子集可以不依赖桌面，但不能更名为正式专项通过。

允许一个测试覆盖多项，但manifest逐子项列出精确测试名和证据要求；所有映射项均通过才完成该项。不得只写父标签、扫描字符串、存在一个按钮、exit0或互相比较同源输出来证明正确。真实桌面暂停时保留未验证，继续不依赖桌面的切片。

## 2. 独立夹具、数值和时间契约

1. 使用测试自有目录和现有F01/F02解析音频，不覆盖用户音频、工程、插件。通道输入含不同频率、脉冲和非零非对称值，float64生成期望，保存输入hash和稳定通道ID。基本sample_rate为16000/48000，channels为1/2/4。
2. Python无状态示例`y=0.5*a-0.25*b`，有状态示例`y=g*x+step*n`，n为每实例从0连续的样本序号。C++用不同公式`y=-2*a+0.125*b+step*n`；v2改变系数以区别代码版本，不只改显示名。六类参数全部真正参与计算、资源或可核验报告，tag变化不得伪造为音频变化。具体示例源和独立oracle分别维护，oracle不import插件/生成wrapper。
3. 基本无状态矩阵：两采样率×三通道数×帧长{1,513,16037}，host127；状态连续性：48000Hz双通道、16037帧，host{1,127,512,1024}。C++主矩阵：两采样率×三通道数、513帧，host{127,512}。另验证额外端口和错误夹具。日常只跑目标和直接影响子集；稳定出口集中跑本矩阵，旧平台要求的其他帧长/分块矩阵继续保留，不以本矩阵缩小它们。
4. 逐样本满足`abs(actual-expected) <= 2e-6 + 1e-5*abs(expected)`；帧数、通道ID/顺序、采样率、有效区间、所选端口精确一致。读取本次WAV/NPY/manifest，不仅检查文件存在。GUI和CLI各自对独立oracle验算。整数/布尔/枚举/路径/身份字段精确比较。
5. 草稿保存防抖500ms，空闲1秒内持久化；测试使用注入时钟/存储失败，不靠宽松sleep。检查队列active≤1、pending≤1，检查结果绑定完整身份/hash；重复20轮无残余子进程或逐轮累积的任务对象。
6. 短试跑默认30秒、C++构建默认600秒，配置和有效值必须记录；超时夹具用短deadline。Python协作取消≤2秒，总回收≤5秒；工作台构建/probe自有子树取消回收≤5秒。消息心跳遵守PERF-01：20ms、10秒、p95≤100ms、max≤500ms，不能改采样窗口掩盖卡顿。
7. 复用协议1MiB、Python源码128文件/8MiB、载荷64MiB边界；UI日志尾部≤256KiB，完整日志每任务≤16MiB，超限报告log_limit并回收检查子树。每种边界分别验证上限内与超限拒绝；输入预算在执行前预检，运行中日志超限停止任务且不激活节点，禁止静默截断源码。与现行生产预算不一致时先核对接口并记录ADR，不直接改测试阈值。
8. 中文、空格、长路径（含超过260字符）和代码内非ASCII字符；重开和诊断位置按文档中的Unicode行/列约定一致。源码检查不得修改输入。受控崩溃只在新建子进程/临时目录触发，不在用户宿主注入访问冲突。

## 3. 必需子用例

### NA-01 草稿与存储（S0，纯服务＋组件）

- **NA-01.a**：真实新建按钮打开编辑面板，粘贴源码、定义参数、保存并重开后正文/声明/ID一致；创建/修改草稿不改变当前图、计算revision、dirty、运行展示或目录。首次Red必须能捕获实际无草稿流程的缺口。
- **NA-01.b**：自动保存防抖与空闲预算通过；注入磁盘满/权限/替换失败，原草稿字节/hash不变，界面明确未保存，正文仍可恢复；显式保存完成后恢复自动保存。
- **NA-01.c**：关闭默认只保存，重开得到同一草稿；检查未过/源码不完整也不向库注册节点。保存失败时不无声关窗丢失；显式放弃与保存的结果可区分。
- **NA-01.d**：两个草稿独立；从内置/已安装节点复制编辑不改原包；非法相对路径、链接逃逸拒绝；草稿根可注入为工作区临时目录。

### NA-02 节点定义与参数（S0/S2，SDK＋组件）

- **NA-02.a**：表单/导入生成唯一逻辑type_id、精确port_id和bool/int/float/enum/string/path定义；默认值、边界和显示元数据复用现有SDK校验，生成声明与表单往返一致。
- **NA-02.b**：重复/非法ID、端口方向/类型、默认值类型或范围、空枚举、非有限数、未支持执行能力全部结构化拒绝并定位字段；拒绝不改草稿最后有效声明或库/图/历史。
- **NA-02.c**：六类参数通过真正控件→controller→冻结参数进入算法/资源/报告；同type两实例不同参数各自产生独立预期，重置默认值/参数撤销重做仍正确。
- **NA-02.d**：声明由表单/导入事务单一维护，wrapper.describe与manifest一致；外部修改声明与面板未保存值冲突时保留双方，不静默覆盖；高级SDK模式也走同一验证。

### NA-03 模板生成（S1/S2，纯服务＋真实runner）

- **NA-03.a**：从用户函数生成Python包，用户无需写协议或重复manifest；实际独立runner执行新包符合无状态oracle，模板生成成功本身不算运行通过。
- **NA-03.b**：状态跨块连续、两实例隔离；prepare/reset/re-run/取消后再次运行状态归零，符合整数n的独立oracle，不受host分块影响。
- **NA-03.c**：命名双输入/双输出按声明处理，共享上游只执行原约定次数；输出ID与所选端口正确，声明/包装错误定位到用户源文件而非只指向生成壳。
- **NA-03.d**：任意无法识别的源码、错误返回结构、未支持能力明确拒绝，不启用算法名分支、不静默生成恒等节点；模板版本与源码hash进入产物和运行记录。

### NA-04 源码与依赖诊断（S1/S2，检查进程＋组件）

- **NA-04.a**：Python语法错误含文件/行/列，可点击定位；C++对应错误在NA-12覆盖。语法阶段只编译/解析，不执行顶层副作用，原源码字节不变。
- **NA-04.b**：缺模块、错误entrypoint、describe不匹配分别返回具体原因；用户顶层代码只在受控子进程运行，UI/宿主无该模块导入及副作用。Python OFF时清楚显示不可执行，旧原生Gain仍可运行。
- **NA-04.c**：修改正文/声明/模板/解释器后旧Ready失效；修复同一行错误再检查成功，诊断只归属当前generation，不能残留旧错误或把旧成功用于新代码。
- **NA-04.d**：依赖缺失不自动安装/联网，环境/解释器版本和hash明确；非法路径、超限源码及损坏包在执行前拒绝，旧可用版本不变。

### NA-05 隔离契约试跑（S1/S2，真实独立进程）

- **NA-05.a**：合法Python独立子进程执行prepare/process/reset，试跑成功有本次输出/身份/hash；输入只读内容hash保持原值，子进程结束可核验。
- **NA-05.b**：缺输出、多输出、错误dtype/shape/帧数/通道顺序/采样率/区间、NaN/Inf逐类拒绝并定位node/port，不自动cast/补零/裁剪来通过。
- **NA-05.c**：顶层异常、prepare异常、运行异常、进程崩溃/挂起后宿主存活且能再次检查合法节点；没有半包/成功标记，错误和日志有界。
- **NA-05.d**：内置模板对独立oracle通过；用户无oracle时仅显示“契约检查通过”，不显示“算法正确/安全/实时已验证”。探针进程隔离不冒充权限沙箱。

### NA-06 队列、取消与身份（S2，纯状态＋进程＋组件）

- **NA-06.a**：慢检查A、修改后检查B，依次投递A的成功/失败/进度/取消，只有当前完整identity可回填；不同草稿/工程同generation与同revision也不串结果。
- **NA-06.b**：编辑、连续Apply/Cancel、切换工程、关面板/关应用覆盖active/pending边界；active≤1/pending≤1、过期pending不执行，旧回调不解引用销毁控件；取消后合法任务成功。
- **NA-06.c**：真实超时/取消/日志洪泛/子进程派生满足预算与自身进程树回收；20轮后活动任务/进程归零，外部无关进程仍存活，旧运行文件不改变。
- **NA-06.d**：慢检查/挂起probe及C++构建期间UI心跳满足PERF-01；代码加载、文件扫描、编译、波形/数值检查均不在UI/设备回调中执行；测试调用栈和线程证据可核验。

### NA-07 原子应用与恢复（S1/S3，文件事务＋catalog）

- **NA-07.a**：只有与当前冻结源码/声明/工具身份匹配的Ready可Apply；相同输入重复点击只产生一个完整包/目录条目，不重复添加工程节点。
- **NA-07.b**：在写包、注册候选、更新索引、刷新目录阶段分别注入失败；上个完整可用版本仍可Run，草稿保留，半包/坏索引不被发现为Available。
- **NA-07.c**：提交前/后模拟进程中断，重启只恢复旧完整版本或新完整版本；包hash/索引校验失败明确报告，不以“目录存在”当完成；孤立产物不成为默认。
- **NA-07.d**：磁盘与内存目录的提交/恢复语义有独立故障fixture；取消或失去工程回填权限时不误改当前图；旧包/输入/运行不可变，受引用版本不被自动清理。

### NA-08 节点库即时刷新（S1/S3，catalog＋组件）

- **NA-08.a**：Python新节点Apply后不重启宿主出现在库中，点击/拖放恰好创建一个节点，精确端口和默认参数正确，Inspector可调参并真实Run。
- **NA-08.b**：刷新保留当前已实现的滚动/过滤条件、现有条目与选择，不额外要求新增搜索功能，不清空画布/拓扑/布局/历史；旧拖拽源、旧菜单/异步选择在目录generation变化后明确取消或重新验证，不悬空。
- **NA-08.c**：旧任务持有旧catalog/factory/模块快照，刷新不产生悬空引用、原地map竞争或描述/工厂半注册；工厂与描述来自同一版本。
- **NA-08.d**：未受管原生/Python目录、默认搜索根/显式路径与重复ID拒绝行为保持原约定；不可通过“后扫描覆盖同ID”实现受管更新。CLI解析同一版本和诊断。

### NA-09 精确版本与工程升级（S1/S3，controller＋runtime）

- **NA-09.a**：新图首次添加固定v1，库Apply v2后原图仍用v1，新建未锁图可选v2；一个工程同type/同受管包只能锁一个版本，不同工程/运行可同时持各自版本，同包新增type不得越过旧锁隐式混用。
- **NA-09.b**：用户显式升级预览列出同包受影响类型及全部实例；兼容升级一次revision/历史项，参数/布局/边/资源/所选输出保持，结果标过期；仅库新增不改未升级图的revision/结果有效性。
- **NA-09.c**：v1慢运行中升级v2并运行，v1成功/错误/进度晚到不污染v2；旧实际音频仍符合v1公式，v2符合v2公式，不仅检查版本字符串。
- **NA-09.d**：升级undo/redo恢复精确版本/模型，计算revision单调；缺旧包/坏hash明确阻止对应运行且保留工程，不自动latest或悄悄替换type_id。

### NA-10 不兼容定义迁移（S3，纯命令＋组件）

- **NA-10.a**：删/改端口、改参数类型/范围导致不兼容时预览明确受影响连接和实例；首版允许拒绝并复制为新type，不默删边/参数/资源。
- **NA-10.b**：安全兼容迁移候选经完整编辑校验后一次提交；验证失败/用户取消/工程已切换时模型、revision、dirty、历史及版本锁不变。
- **NA-10.c**：未知节点/未知参数/opaque JSON及所选输出无损保留；缺包图仍能查看/另存/补包恢复，Run严格拒绝，不把未知节点改成Gain。
- **NA-10.d**：同工程多实例参数合法性分别验证；部分实例失败不能只升级一半；新旧参数摘要/Inspector/运行快照一致，撤销恢复全部实例。

### NA-11 工程格式、携带与重放（S1/S3，IO＋CLI＋独立读取）

- **NA-11.a**：既有schema 1 fixture读写/运行不变且不自动升级；引入受管节点的工程明确采用schema 2并持久化精确锁；旧只支持schema 1的读取器对schema 2显式拒绝，不误运行。
- **NA-11.b**：已有工程首次迁移前备份原字节并校验，备份/临时写/替换失败逐项保留原文件与可打开状态；新未保存工程无原件时不造假备份；普通legacy保存政策不变。
- **NA-11.c**：Save/Save As/导出后移动至受控中文/空格/长路径目录，删除测试自有原草稿/原插件后重开仍从携带包正确执行；相对输入资源解析、版本/代码/环境报告准确，旧原件不被修改。
- **NA-11.d**：缺包/缺环境/被改源码/hash不符时结构化失败、无成功标记；补回正确包可恢复；本次GUI/CLI产物各自符合oracle，旧run字节/hash不被新版本改写。

### NA-12 C++独立构建（S4，真实编译器＋SDK消费者）

- **NA-12.a**：内置C++模板只改算法正文即可生成独立工程，从发布安装SDK编译DLL，无宿主/JUCE/源码树依赖，宿主EXE hash不变；在仓库外测试目录完成一份独立消费者。
- **NA-12.b**：语法/链接错误映射回用户源码，缺工具链/SDK/ABI/架构分别诊断；构建失败保留草稿与旧版本，不修改全局环境或自动下载依赖。
- **NA-12.c**：中文/空格路径和正文中的引号、反引号、`$()`不被当shell执行；生成构建文件和参数数组可审计，编译只在自有工作目录，取消不杀无关构建。
- **NA-12.d**：manifest与DLL内嵌描述由同一声明生成且完全匹配；同逻辑版本内容变更不可覆盖旧包；新DLL确实执行C++独立公式，不能用Python代替C++通过此项。

### NA-13 原生probe与重启激活（S4，独立进程＋宿主生命周期）

- **NA-13.a**：缺导出/错误ABI/描述不符/受控崩溃/挂起DLL仅在probe进程被检测和回收，宿主存活，当前可用Gain/旧插件可继续执行。
- **NA-13.b**：验证新DLL后显示PendingRestart，当前进程继续旧版本，不替换已加载路径、不热卸载；宿主未重编，关闭应用时任务/实例回收先于模块释放。
- **NA-13.c**：用户“保存并重启”时草稿/工程保存失败取消重启；成功时任务安全回收、同EXE重启恢复原工程和精确新锁，新实际输出符合v2公式，旧运行仍v1。
- **NA-13.d**：待激活包损坏/启动失败保留工程、旧索引与可恢复诊断，不自动改锁伪装成功；两个实例状态隔离。正式运行未隔离的边界清楚可见，不把probe当作原生安全沙箱。

### NA-14 编辑面板交互（S0/S2，组件＋桌面）

- **NA-14.a**：内置面板提供源码输入/复制粘贴、文本撤销重做、保存状态、诊断跳转、检查/取消/应用；错误后继续编辑不丢正文，关闭默认不注册节点。
- **NA-14.b**：源码编辑焦点下Ctrl+Z/Y只作用文本；回到工程控件时原拓扑快捷键仍有效；多面板/关闭回填安全，不出现焦点回调重入覆盖草稿。
- **NA-14.c**：自动保存、检查、Ready、Applying、Available/PendingRestart与失败的状态文字符合实际，不因旧结果/日志尾部或关闭事件显示假成功；只有契约通过不显示算法正确。
- **NA-14.d**：真实100/150/200% DPI及逻辑1100×700、1440×900，中文/长路径、长声明/诊断不遮挡关键控件；保留截图和输入步骤。不得未经授权改系统DPI，暂停时not_verified。

### NA-15 无功能回退（S1～S5，旧契约累计）
