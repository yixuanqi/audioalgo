# 0037 — 用户草稿文件与恢复副本分离

2026-10-24，按用户指定位置保存的授权及 `plan_authoring_file_locations_and_launch.md` 实施。

用户文件继续采用单一 `AudioAlgoDraft/1` 字节格式，文件名不决定草稿/type/package 身份。显式文件保存采用原子替换和预期旧字节冲突检测；新目标不覆盖已有文件。恢复按 ID 存储继续可用。

用户文件 generation 与恢复 generation 分开。500ms 防抖继续用于恢复；恢复成功不代表用户文件已保存。新宿主启用文件选择式保存；旧嵌入调用未提供文件选择适配时，保留原按 ID 保存契约作为兼容入口，不能以旧入口测试替代新宿主文件流程验收。

另存为仅成功后绑定新路径；取消或失败不改变原绑定。目标/文档/请求身份参与异步接收，较旧保存不能标记新编辑已保存。恢复路径改变和检查工作目录改变不得移动节点库或更改工程精确锁。

恢复侧文件 `<id>.aadraft.binding` 使用 `AudioAlgoRecoveryBinding/1` 加四个字节长度字段，分别保存草稿 ID、generation、原文件 UTF-8 绝对路径、预期原文件字节。文本与绑定分别原子提交；读取必须核对 ID/generation 及原文件格式，撕裂或损坏的绑定只产生警告并解除目标，不丢恢复文本。显式保存即使没有正文编辑也会使恢复绑定失效并重写；旧恢复完成须同时匹配捕获的目标路径和预期字节才能更新恢复基线。

草稿文件选择器不随无关工程切换失效，但仍受宿主关闭及面板存活令牌约束；保存、覆盖确认各请求使用一次性回执，重复或晚到交付不得重绑文件。覆盖确认针对后台捕获的旧字节，最终替换前再做内容冲突检查。此保护不等于与不合作的外部写入者之间拥有跨进程文件锁。
