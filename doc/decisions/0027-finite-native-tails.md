# 0027 — 有限原生尾部与补零恢复

2026-10-23。AR-15.e 的有限补零切片。

尾部与延迟单独声明。已知且支持补零的固定帧算法可以保留精确 tail_frames，并声明 maximum_zero_padding_frames，预算必须覆盖自身算法延迟、尾部与最多 F−1 末帧填充。未知尾部、预算不足/缺失或要求尚不存在的 flush API 在创建实例前拒绝。Speex 没有公共 flush API；其补零仅恢复已知重叠延迟，保留尾部为0，预算959。

纯计划按拓扑累计尾部（串联相加、合流取最大）和延迟，检查路径累计溢出。JUCE 的实际延迟必须与计划一致。末端保留 N+tail，raw 保留 N+tail+latency，仅按声明延迟裁剪一次。报告新增源帧数、保留尾部、源结束后的全局补零时长与 raw 有效长度。较短分支完成后静音，不继续调用算法生成额外样本；固定帧最后一帧中的超额结果不发布。

接受零补帧并不保证算法拥有 flush 功能。此 profile 的 drain 是有限零输入处理，不调用或伪造 flush。当前显式保留尾部的准入限于补零固定帧；任意输出速度、逐端口EOS/完成确认仍为后续契约。AR-15.e 映射保留 remaining_contracts，AR-15/R5/P2 不据此通过。
