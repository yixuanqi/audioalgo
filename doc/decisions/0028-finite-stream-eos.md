# 0028 — 逐端口有限流结束

2026-10-23。内部 C++ 固定帧流协议，不改变发布的 DLL C ABI v1。

纯计划按节点输入对齐延迟和每条上游尾部计算每个输入独立的结束位置；短输入结束后继续为另一输入提供声明的零样本。每次借用 view 携带 frames_before_eos 和 end_of_stream，前者描述当前物理输入时间线中 EOS 前的前缀（包含已声明的对齐延迟），并非 AudioBuffer 的逻辑有效区间。完整帧剩余部分为补零。NeedMoreInput 仍按实际逐端口 consumed/produced 推进。

每个输出独立确认 finished。不得提前完成、重复完成或写入已完成端口。节点可以按固定帧产生超过逻辑结束位置的填充结果，边界只发布声明范围；也可在逻辑前缀产生后完成，未写部分清零。漏报完成按无进展预算失败。图结束时再次检查所有输出确认，禁止缺失 EOS 的成功返回。

空流发送零容量 EOS 握手，不凭空调用一帧算法。该握手同样有无进展预算与异常诊断。终止前后保留取消检查。Speex 真实薄适配确认最后补零恢复帧，继续不调用不存在的 flush API。

原有帧内部分消费 fixture 仍保留原计数和 oracle；新增补偿输入相差3样本、两输出不同推进速度、空流和错误确认用例。EOS 的指针/计数存储在 prepare 分配，包含最终 EOS 回调的零分配检查通过。任意跨帧异步流和不同输出各自尾部/有效区间的描述扩展未实现，当前 AR 映射继续精确保留这些缺口。
