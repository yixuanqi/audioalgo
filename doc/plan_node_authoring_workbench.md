# 应用内自定义节点工作台

## 1. 本次任务与适用范围

用户要求在本项目内完成“点击按钮→编辑/粘贴源码→按规范封装→源码检查→成为可用节点”的闭环。本方案与[测试准则](testing_node_authoring_workbench.md)、[TDD执行规程](agent_loop_node_authoring_workbench.md)共同指导开发。2026-10-23首次编写时仅交付文档；2026-10-24已进入实施，从[唯一当前摘要](development_status.md)与NA0008接续，以下待建描述不作为当前实现证明，也不重做已完成草稿闭环。

本专项采用内置轻量代码编辑面板作为必需入口，第三方编辑器为后续可选入口。顺序为Python闭环→版本/恢复完善→C++独立构建闭环；不先建设完整IDE。关闭面板默认保存草稿，“检查并应用”成功才进入本机节点库。此处“应用/发布版本”均指本机受管存储，不涉及上传或对外发布。

本专项已获启动授权，按本方案S0～S5推进，优先于旧状态里的独立P3下一行为；原R0～R6、G0～G6、NED、UPN及独立数据评测任务保留，不重做已完成行为，不把本专项当作整个平台完成。工具权限、真实桌面暂停和不自动提交/推送等边界保持有效。

## 3. 用户流程与状态

节点库增加“新建自定义节点”；已支持编辑的受管节点提供“编辑源码”。内置节点与只读第三方插件可“复制为自定义节点”，不得直接改安装包或任意用户源文件。新建选择Python/C++，填写名称、逻辑type_id、输入输出、参数和无状态/有状态模板。表单维护声明的唯一权威，生成manifest与wrapper；高级用户可导入现有SDK包作为草稿，但冲突必须显式诊断，不能留下两份互相不一致的声明。

面板至少有定义、源码、诊断/试跑三个区域：基本撤销重做、行列定位、保存状态；支持中文、空格路径及长源文件。编辑器内文本撤销只改草稿，不应误触工程Ctrl+Z；画布/工程快捷键原行为仍保留。

状态以值模型表达：`Draft → Checking → Ready → Applying → Available`；C++激活另有`PendingRestart`；失败/取消回到可继续编辑的Draft并保留诊断。`Ready`绑定确切的草稿generation、声明hash、源码树hash和工具链/环境身份；源码、定义或环境改变后旧Ready失效。连续Apply相同内容幂等，最多产生一个版本；重复点击不重复创建节点。

草稿自动保存默认500ms防抖，空闲后1秒内落盘；使用注入时钟测试，不用真实sleep验证所有边界。自动保存采用临时文件+验证+原子替换。存储失败明确显示“未保存”，不关闭后丢失正文。正常关闭只保存，不检查/激活；未保存失败时提供保留面板或显式放弃选择，不伪装成功。未来“关闭时检查并应用”是可选设置，不属于本版必需项。

检查与应用后台执行，期间继续编辑会形成新generation；旧检查/构建的晚到消息不能把新草稿标为Ready。切换工程、关闭面板、关闭应用的回填权限分别校验；关闭不自动杀无关编辑器/编译进程。

## 4. 封装与源码约定

### 4.1 Python

首条可用纵向切片为无状态同格式PCM transform，随后补有状态、命名多输入输出和六类参数。沿用现有`AudioPort`、`Context`和manifest schema，而非让用户手写协议。

基础模式建议用户只实现一个固定入口，例如`process(inputs, params, state)`，输入/输出均为按port_id命名的`[channels, samples]`、C-order float32数组；返回输出字典。这是待实施编写接口，必须先定契约和测试再接入。生成wrapper负责`describe/prepare/process/reset`、元数据传递和结构诊断；初版同格式N入N出，禁止隐式改采样率、通道、长度或自动dtype转换来掩盖错误。

有状态模板提供初始化与重置钩子；每节点每运行独立state，跨块连续，重跑/取消后状态重建。高级SDK模式允许直接使用现有完整类接口，依然经过同一校验、快照和试跑。声明不支持的clip/非PCM/动态尾部等能力明确拒绝，不能自动降级为普通block。不得为特定用户算法增加画布/编译器/调度器type_id分支。

### 4.2 C++

生成独立插件工程、manifest与C ABI适配壳；用户编写纯算法和明确的prepare/process/reset入口。只依赖安装的Node SDK，不链接宿主或JUCE，不把源码复制回通用宿主target。沿用C ABI v1目前支持的PCM与固定帧/已知延迟契约；不承诺部分消耗、动态延迟、任意尾部或跨编译器ABI。

用户正文不进入字符串拼接的shell命令。构建参数按数组传递，工作目录、输入和输出明确；基本模式使用生成的构建文件，禁止隐式执行粘贴正文中的shell/CMake指令或自动下载依赖。支持的高级工程导入范围另行说明，不能在本版宣称任意C++源码都可自动封装。

### 4.3 外部编辑器

本版内置面板必需，外部编辑器/LSP/高级补全为可选后续。以后接入时使用保存检测+明确“检查并应用”，不用外部进程退出推断用户关闭文档；文件监听防抖并重新核对内容hash。外部修改与内置未保存修改冲突时显示冲突并保留两份，不静默覆盖。可选能力不得作为本版完成的前置条件，也不能未经测试显示为已支持。

## 5. 服务与模块边界

建议新增`audio_node_authoring`纯应用服务及`NodeAuthoringPanel`展示适配，名称均为待建，可按最小实际边界调整并记录。服务提供草稿文档、模板生成、检查/构建请求、受管包存储和应用事务；不依赖JUCE控件或具体算法。UI仅发送意图、展示状态、把诊断定位到源码，不持有可执行工厂或直接启动编译器。

重用RunService/PythonTask的真实执行、身份、代码冻结和产物读取；独立试跑也是worker请求，不运行在消息线程/设备回调。原生probe是独立子进程，正式原生执行仍复用backend；本版不新增原生执行隔离backend，不把probe成功描述为宿主运行安全保证。

目录以不可变`CatalogSnapshot`呈现，run拥有解析后的factory/module lease。旧目录快照在旧任务回收前存活；controller和View不得持有已释放snapshot的引用。受管解析是通用能力，原外部目录扫描规则和重复ID错误不改变。可原子替换的稳定catalog facade或显式shared ownership二选一，先为生命周期写Red，禁止原地修改worker正在遍历的map。

工作台异步身份至少包含workspace/draft ID、draft_generation、源码/声明hash、request_id；涉及当前工程的操作另带project_id、session epoch、document generation及预期revision。接收入口统一校验，不能只比较revision。草稿变更不改变计算revision；目录刷新本身不改工程；向工程添加/升级节点通过controller事务改变一次计算revision并标记结果过期，布局拖动依然只改布局。

## 6. 检查、试跑与预算

1. **静态声明/语法**：端口/参数/默认值沿用SDK验证；Python语法编译不执行源码，语法行列和文件可定位；C++编译诊断映射回用户源码（生成壳使用稳定source map或`#line`）。检查进程不得在宿主/UI中import或加载待检查DLL。
2. **环境/构建**：锁定解释器、依赖、SDK/ABI、平台架构和编译器；缺失依赖报告缺什么，保留旧可用版本；不后台pip install、不联网修环境、不重编宿主。
3. **隔离契约试跑**：对不可变源码包运行语法、导入/描述、prepare/process/reset；检查输出端口、float32、形状、帧数、通道ID/顺序、采样率、有效区间与有限值。有状态、双实例、异常后恢复需真实执行，不只检查类名或函数签名。
4. **算法验证**：内置模板有独立解析oracle；任意用户算法只报告“契约试跑通过”，数值/质量正确性需用户提供独立参考，不能用代码检查保证。

工作台任务队列最多1个active、1个pending最新请求；新草稿替换旧pending，active可取消，迟到结果隔离。默认短试跑墙钟30秒、C++构建600秒，可配置并记录；超时测试注入短deadline，不每次等满预算。Python协作取消≤2秒、总进程树回收≤5秒；构建/probe子树取消回收≤5秒，只限自身Job Object，不能结束其他VS/编辑器进程。复用现有协议1MiB、Python代码128文件/8MiB、任务载荷64MiB上限；日志UI保留尾部≤256KiB，完整日志每任务≤16MiB，超过则给明确log_limit诊断并停止检查/回收子树，不激活候选。新增上限是可测试契约，不能为变绿临时放宽已有上限。

构建/试跑期间按PERF-01测20ms消息心跳10秒，p95≤100ms、最大≤500ms。重复20轮成功/错误/取消，active/pending对象和进程回收后归零，无任务引用逐轮保留。进程隔离用于崩溃/挂起恢复，**不是权限安全沙箱**；静态检查不证明源码安全。普通本机算法工作流不额外加入审批对话，但产品必须准确说明此边界。

## 7. 草稿、不可变版本与原子应用

建议布局（待实施；测试注入工作区内根目录，不直接写真实用户AppData）：

```text
<authoring-root>/drafts/<draft-uuid>/       # 源码、声明、草稿generation
<authoring-root>/staging/<request-uuid>/    # 本次冻结输入、构建与probe输出
<authoring-root>/packages/<package-id>/<content-hash>/
<authoring-root>/index.json                # 可用/默认/待重启版本索引
```

受管packages不直接放进原默认plugins扫描根让多个同type_id版本一起扫描；由版本解析器为本次目录选出精确包，再走共同注册入口。跨路径/链接逃逸、重复输入、内容变动、hash不符均拒绝。用户主动选定的外部源文件只读复制为草稿；不覆盖外部原件、安装包、用户音频和旧运行产物。

应用以Ready对应的冻结包为唯一输入：先在staging完成检查、产物与hash，候选目录注册成功，再原子提交完整包及权威索引。发布中的崩溃/磁盘满/目录刷新失败不得留下半包或把失败版本标为默认。磁盘索引与内存目录使用明确提交/恢复协议；重启只能得到旧完整版本或新完整版本。未被索引引用的完整包可作为待回收产物，不冒充已激活。自动回收不得删除工程/运行仍引用的版本。

版本键至少含package_id、逻辑type_id、显示版本、源码/声明hash、产物hash、wrapper模板版本、SDK/环境身份。每次改动生成新内容版本，已激活包不可写。相同输入幂等；显示版本相同但内容不同必须诊断或生成明确新版本，不能借“版本号没变”覆盖旧产物。失败保留完整诊断与草稿，上一个可用版本仍能运行。

## 8. 工程版本锁、升级与兼容

首版明确限制：**同一工程内，同一个逻辑type_id只绑定一个精确受管版本；同一个受管package也只绑定一个内容版本**。不同工程和旧运行可以持有不同版本，不同包的类型可自由组合；多节点包的升级需统一检查该工程使用的同包全部类型/实例，不能把同一包两个版本同时交给原重复ID扫描器。这避免为首版引入同图同type/同包多版本的全调度重构。不能悄悄把type_id改成hash或假装同图多版本已经实现。

“检查并应用”使新版本进入本机库，不自动升级已有工程。工程已绑定v1时继续添加同包type仍用v1；使用v2需要明确“升级本工程中的同类节点”，预览同包所有受影响类型/实例/端口/参数，一次controller事务统一升级。v1不含新增type时需先升级包，不能越过锁隐式混用。其他工程、旧运行和旧包不受影响。新图首次添加时解析一次版本并固定，后续绝不能按latest悄悄重解析。

端口/参数不兼容时先给迁移预览；首版允许安全拒绝并提供“复制为新type_id”，无需自动猜连线。不静默删除边、参数、资源、所选输出或未知字段。兼容升级保留所有连接/布局/实例参数；参数按明确迁移规则验证。升级/撤销/重做均形成新的单调计算revision；运行中的旧任务始终持旧快照，其结果不能覆盖新工程状态。仅新增库版本不使未升级工程的结果过期。

由于旧schema 1宿主会忽略未知字段，不能仅往schema 1塞版本锁后声称旧宿主也会正确执行。计划新增schema 2用于包含受管版本锁的工程，新宿主同时读取schema 1/2；legacy工程未使用本功能时继续schema 1原语义。首次保存含受管节点的已有工程前明确提示格式升级，按原格式政策备份原字节到`.schema-1.bak`并验证，任一步失败原文件不变；新建未保存工程无旧文件时直接保存schema 2。旧宿主对schema 2应明确unsupported，不能误跑别的版本。

schema 2锁、相对资源和受管包引用的精确字段在实现时先写迁移契约及独立fixture。保存/另存为/导出须能携带所需源码、声明、必要资源及可定位的产物，移动到受控新目录后重开可运行；不携带API密钥或整个Python环境。缺包/缺环境/hash不符明确标记Unavailable并保留数据，不回退到latest。GUI/CLI共用解析和运行身份；运行报告保留本次准确代码/版本/环境和实际参数。

## 9. C++激活边界

C++工作台完成模板→后台独立构建→独立probe→安装新版本→待重启激活。缺工具链、编译失败、ABI错、缺导出、probe崩溃/挂起均不加载进宿主，旧版本保持可用。源码检查/构建/probe不等于任意未来输入都安全，正式C++运行仍为当前进程内模式。

首版不要求运行中热卸载，也不必实现原生节点即时切换。UI显示“已验证，重启后可用”；用户明确触发“保存并重启应用”才执行重启协调：未保存工程/草稿先保存，失败则取消重启；取消/回收当前任务，持久化待激活索引和恢复工程，再正常退出/启动同一EXE。不得强杀当前宿主、替换已加载DLL或让应用源码参与插件构建。用户不重启时继续使用旧版本。

启动时确认候选包/锁，成功恢复工程；失败给结构化诊断并保留原索引/工程供恢复，不能擅自把工程锁换回另一个版本。最晚在S4提供无需手工拷贝DLL/配置搜索路径的产品闭环。以后若做原生热激活或正式执行隔离，另立契约，不混入本版验收。
