# 自定义节点文件位置与 Windows 启动权限修复方案

日期：2026-10-24。状态：NA0024～30 已实现用户草稿文件、恢复分离、目录选择及正常运行副本的自动化子集，结果见 [当前摘要](development_status.md) 和 [用法](custom_node_files.md)。真实桌面选择器、Release 新进程与 DPI 仍未验证，本方案完整验收未通过。以下条款继续作为验收依据，不能把计划项整体视为通过。

## 1. 目标与已核实事实

用户应能选择自定义节点文件的保存目录和名称，并从任意受支持的位置重新打开。目录权限失败时，应用必须保留编辑内容、提供调整入口，不把存储失败显示成 Python 源码错误。

本次只读排查发现：

- `configured_authoring_root()` 仅支持环境变量 `AUDIOALGO_AUTHORING_ROOT`，否则使用用户 AppData 下的 `AudioAlgo/authoring`，没有图形设置入口。
- `DraftStorage` 以 `save(Draft)/load(id)/list()` 为接口，`FileDraftStorage` 将文件映射为固定 root 下的 `<id>.aadraft`。当前打开草稿也是固定目录列表，不能浏览用户文件。
- 面板把自动保存与用户保存共用同一个保存基线，尚未区分“已有恢复备份”和“已写回用户文件”。
- 报错时运行的是 Release EXE；当时读取的进程为 Low Integrity（S-1-16-4096），EXE、bin 目录及仓库均有继承的 Low Mandatory Level 标签。普通用户环境在 AppData 的唯一临时目录中创建/写入/读取/清理均成功，普通和扩展路径结果一致。

这支持将当前故障拆成两件事：用户文件缺少位置选择；发布 EXE 的完整性标签导致普通目录写入受阻。Release/Debug 配置本身不决定 Windows 完整性级别。增加文件选择器不能单独消除进程权限问题。

本方案针对**节点草稿文件**的另存为。`development_status.md` 当前列出的“工程 Save As 携带输入音频与精确包”是另一条行为，不能用本方案替代或误记为完成。实施时先核对最新摘要，保留 NA0023 及后续已有实现。

## 2. 用户流程

### 2.1 新建、保存与打开

1. 新建草稿先进入内存编辑状态，允许不完整源码/声明；不修改工程、节点库或计算 revision。
2. 首次点击“保存”或 Ctrl+S，打开文件选择器，用户选择目录和文件名，默认扩展名 `.aadraft`。默认位置只是建议，可自由选择其他受支持的可写位置。
3. 保存成功后显示完整路径及已保存状态；后续保存写回相同路径。
4. 增加“另存为…”及 Ctrl+Shift+S。用户取消时不改变文件绑定、保存基线或编辑内容；目标存在时明确确认覆盖。
5. “打开草稿…”使用文件选择器打开 `.aadraft`；旧固定目录中的草稿保留“恢复草稿/最近草稿”入口。读取验证完成后才采用新文档，当前有未保存修改时先走保存/放弃/取消流程。
6. “保存并关闭”首次需要选路径；选择取消或保存失败时保持面板打开。关闭不得隐式 Apply。保留明确的放弃操作。
7. 可增加“导出 Python 源码…”便利入口，但 `.py` 不包含完整声明，不能代替完整草稿保存或将其误标为完整文件已保存。源码导出放在基本闭环之后。

旧默认目录中的 `.aadraft` 不批量搬迁或重命名。打开旧文件时将其实际位置绑定为已有用户文件，保留保存写回和关闭语义；用户显式另存为后才切换绑定。恢复记录中的原路径属于会话元数据，另行版本化保存，避免为位置选择破坏既有 `AudioAlgoDraft/1` 编解码或改变节点身份。

### 2.2 自动恢复

保留现有 500ms 防抖与空闲 1 秒内的恢复持久化预算，不因新增文件选择而取消自动恢复。

- 未命名草稿自动写恢复副本，不在后台弹出另存为窗口。
- 恢复备份与用户文件保存各有独立 generation 基线；恢复成功只显示“已备份，文件未保存”，不能清除用户文件的未保存标记。
- 第一版默认不让恢复任务覆盖用户文件；显式保存写回用户文件。若以后增加“自动保存到原文件”，须提供可见开关并遵守外部修改检测。
- 关闭时仍按明确的用户文件保存流程处理；显式放弃可以关闭，但不得把未写回的文件标为已保存。
- 启动恢复明确说明恢复副本的位置、原文件路径及更新时间；冲突时保留双方供选择。

这改变了旧“自动保存即统一 saved”的状态含义，实施前须记录补充 ADR，并增加独立验收依据；不能只改旧断言以获得 Green。旧原子恢复、防抖、失败保留契约继续成立。

## 3. 文件与内部目录分工

| 内容 | 位置与管理规则 |
| --- | --- |
| 用户节点文件 `.aadraft` | 用户选择任意受支持的可写目录、名称；一个文件包含源码、声明、ID、generation |
| 恢复副本 | 可设置的恢复目录；故障时明确“尚未备份”，用户仍可继续编辑并另存为 |
| 检查/构建缓存 | 可设置的工作目录，每请求独立子目录；只清理已完成且未引用的临时内容 |
| 已应用节点包与索引 | 稳定、持久的节点库目录；精确内容 hash 和版本锁语义保持，不作为可随意清理的缓存 |
| 工程携带包 | 保留既有工程相对路径和精确解析规则；移动草稿不改工程锁或已安装版本 |

设置界面显示实际生效路径、来源（默认/用户设置/环境变量）和“更改…”入口。程序以实际的唯一临时文件创建、写入、读取、重命名/替换和清理验证所需能力，不只检查目录存在或只读属性；探针不覆盖用户文件。

环境变量继续作为开发/自动化覆盖，优先级为：显式环境覆盖 > 已保存设置 > 默认值。覆盖生效时 UI 必须说明，不能显示“已修改”却仍用旧覆盖目录。

配置文件本身不可写时，允许当前会话采用可用目录，但显示“仅本次会话，设置尚未持久化”；不伪报下次生效。默认目录不可写时提供选择入口，不无提示改到临时目录，更不能从临时目录恢复一个假的“空节点库”。

工作目录改变不应改变节点库目录。节点库目录的变更第一版作为显式维护操作：检查/Apply/Run 空闲，未保存内容处理完毕后，复制全部版本和索引到暂存区、逐文件验证、提交设置后再切换；源目录保留。失败维持旧配置和旧目录。若暂不实现安全迁移，就只开放“下一次正常启动使用”的路径设置，并明确旧版本仍需迁移，不能提供会丢失精确版本的即时切换按钮。

## 4. 代码修改边界

下列是拟建职责，实施前检查实际代码，避免另建重复框架。

1. `libs/audio_node_authoring/Draft.h/.cpp`：复用现有 `AudioAlgoDraft/1` 编解码和大小校验。增加按显式文件路径读写的纯文件文档服务；保留按 ID 的恢复存储以兼容旧草稿。编解码保持单一实现，独立验收读取器不得复用产品编解码。
2. 草稿会话新增文档文件绑定（可空）、用户文件保存 generation、恢复 generation、预期原文件 hash，以及保存目标 generation。位置是会话元数据，不进入算法输入，不因改文件名改变逻辑 type/package ID。另存为保留草稿身份；“复制为新节点”才产生新身份。
3. `apps/editor/NodeAuthoringPanel.h`：增加路径显示、保存/另存为意图和两种持久化状态；保留已修复的取消结果撤销及放弃关闭意图。文件选择由宿主注入，文件读写在 worker 执行，不能在 UI 线程检查整个节点包。
4. `apps/editor/EditorWorkspace.h`：复用异步文件选择/生命周期设施，增加打开外部草稿和保存目标选择；选择器与保存请求带文档/请求/目标身份，晚到回调不得覆盖新草稿或新绑定。选择器适配应可注入测试结果，正式桌面验收仍需真实选择器。
5. `Main.cpp` 与 `configured_authoring_root()` 所在宿主配置层：统一解析有效目录，将恢复、缓存、节点库配置注入各服务；纯算法/SDK 不依赖 GUI。保留环境覆盖和 CLI/GUI 共同精确版本解析。
6. `scripts/build_and_run_editor.ps1` 及后续发布入口：加入部署产物/启动权限检查；构建输出和正式可运行发布目录分开，不让普通发布品继承受管开发工作区的低完整性标签。

继续复用原子临时写入→读取校验→同目录替换；保存前后检查预期文件身份/原字节，外部修改时提示冲突并保留双方。临时文件必须与目标同目录，避免跨卷 rename 被误当作原子替换。损坏文件、超限文件、链接/重解析路径按现有防护策略明确拒绝，不能去掉路径保护来支持新选择器。

连续保存按同一文档串行化；每个任务捕获自己的目标路径和内容快照。A 位置的旧保存完成不能将 B 位置或较新编辑标为已保存。保存/取消/工程切换不得改变已排队 Run 持有的代码、catalog 或版本身份。

## 5. Windows 权限与发布修复

1. 分别检查进程令牌完整性级别、EXE 强制标签及所需目录的实际可写性。进程是 Low 时，提供针对性的诊断；普通 ACL 的 FullControl 不应被误当作足够证据。
2. 在正常用户权限的发布流程中，将产物部署到明确的正常发布目录；检查最终 EXE 标签及实际新进程令牌，而不是假定改名、复制或选择 Release 就能修复。不能把仍继承 Low 标签的目录作为合格发布出口。
3. 不自动修改整个仓库的受管权限、不降低 AppData 的完整性要求，不以管理员运行作为正常使用前提。不在程序内静默提权或更改安全设置。
4. 已有低权限实例不会因用户再次双击就必然被替换；结合现有单实例行为，提示保存/备份内容、正常关闭旧实例后再启动已验证的发布品。不得强杀、绕过单实例或丢弃未保存草稿。
5. 若缓存不可写，禁用相应检查/Apply 并给出“更改工作目录/查看详情”；编辑、复制和可用目标上的保存继续工作。存储错误显示用途、路径、系统错误码和恢复操作，不填充虚假的源码 `0:0` 定位。

真实桌面仍暂停。本轮方案不授权自动关闭/重启用户窗口；后续自动化可以验证组件与独立无窗口子进程，正式桌面状态单列。

## 6. TDD 切片及通过准则

不重新制造 NA0001～23 已完成行为的 Red。以下新增用例绑定原 NA-01/02/04/07/11/14/15/16 的实际覆盖，必要新增用例单列，不替代原 68 项。

### A：用户文件保存/打开

先增加生产面板首次保存选择路径的 Red，再最小实现。必须满足：

- 未命名草稿保存只在显式操作时请求选择器；取消选择后内容、身份、文件绑定、dirty 均不变。
- 用户指定的中文/空格/超过 260 字符目标实际写入成功；独立按字节解析 `.aadraft`，源码/声明/ID/generation 与本次输入一致；从该文件重新打开一致。
- 原文件、已有不同目标、其他草稿和工程字节/hash 不因取消或失败变化。
- 权限拒绝、磁盘满、校验/替换失败均保留内容和未保存标记；更换合法目标后可恢复保存。
- 外部修改不能被静默覆盖；明确覆盖确认针对当前目标，不沿用已失效确认。
- 较旧保存完成不清除较新编辑；另存为过程中旧保存、取消选择器、切换文档、关闭回调均不污染新目标。

### B：恢复和关闭状态

- 恢复写入仍满足原 500ms/1 秒预算；通过注入时钟验证，不放宽等待阈值。
- 恢复成功不把用户文件标为已保存；恢复失败不阻止用户在可用位置显式保存。
- 保存并关闭在选择取消/保存失败时保持打开；显式放弃能关闭；未保存状态下从应用退出采用同一契约。
- NA0009 两条取消晚到 Ready/失败保存后检查中放弃关闭继续通过；正式回归使用生产面板。

### C：配置、缓存与版本隔离

- 默认不可写时可选择工作目录并重新检查成功；环境覆盖、设置持久化失败/损坏诊断均可重跑。
- 一次真实 Python 检查→Apply→画布 Run 产物通过独立数值 oracle，工作目录改变后旧节点包、工程精确锁及旧运行快照不变。
- 清理缓存不会删除节点包；节点库迁移失败维持原索引/目录/配置，成功后保存的旧工程仍按锁运行。
- GUI/CLI 解析一致；Python OFF 的纯草稿保存/打开仍可用，不将 Python OFF 测试称为 Python 执行通过。

### D：启动权限与受影响回归

- 正常发布 EXE 的标签、新进程令牌及用户自选目录实际写入全部核验；仅“能启动”不算通过。
- 测试自有低权限/不可写 fixture 在操作前给出明确存储诊断，内容可恢复；不修改用户目录标签。
- 运行直接受影响的草稿、保存、关闭、取消、Apply、工程精确重开/携带、运行身份及缩放连线/右键多选/负坐标回归。公共配置边界变化时补 CLI、Python OFF 和纯库消费者。
- 必需真实桌面选择器、正常发布启动和 DPI 验收在恢复授权前保持 not_verified；最终稳定出口完成规定矩阵，不用组件测试替代。

每片保存 Red/Green 原始命令、source/EXE 身份、JUnit 及独立实际文件核验到新的 `build/reports/loops/` 目录，更新精确测试绑定和唯一摘要。缺执行、失败或外部证据不足不得记 passed；文档编写本身不触发产品全量构建。

## 7. 实施顺序

先实现用户文件的保存/另存为/打开和失败保留，同时隔离恢复基线；接着提供工作目录设置及权限诊断；再完成正常发布目录/启动检查和节点库路径的安全维护。每次只闭合一个行为。全部完成后恢复最新摘要中工程 Save As 携带等剩余 NA 主线，不扩无关 P3，不自动提交、推送或发布。
