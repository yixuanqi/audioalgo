# 全部架构重构持续开发授权

## 1. 用户授权与任务范围

用户已明确授权：**一次授权，持续自验证、自迭代，直至全部重构完成。**

本授权适用于当前 audioalgo 工作区的既定 [R0～R6 重构方案](plan_architecture_refactor.md)，细则按 [架构验收](testing_architecture_refactor.md)、[Agent规程](agent_loop_architecture_refactor.md)及 [当前R2任务卡](plan_agent_next_r2.md)执行。它将任务范围从“完成下一阶段”明确扩展为“完成所有剩余阶段及累计验收”；不扩大产品功能边界，不更改验收阈值。

从实际源码、最新Review和证据恢复第一条未完成行为；规划时接手点是RF0006的参数Undo缺陷。若它已被修复，先验证并继续下一项，不重复搭建或人为制造Red。保留已有未提交/未跟踪修改。

## 2. 持续推进顺序

| 阶段 | 持续执行的内容 | 转入下一阶段的规则 |
| --- | --- | --- |
| 当前修复 | 关闭最新Review的实际缺陷，防止历史与命令语义回归 | 行为修复和受影响回归通过后继续 |
| R2 | 命令/历史、纯应用控制层、View接入、生命周期、工程兼容AR-13 | 完整验收；外部证据缺失准确挂账并继续不依赖它的工作 |
| R3 | 自动参数表单、View职责拆分、真实交互和数值证据 | 按AR-10/11及原UI/NED要求验收 |
| R4 | 第二算法ChannelSwap、独立消费和新增算法不改通用界面的扩展证明 | R0～R4累积通过才称基本解耦完成，随后继续 |
| R5 | 通用任务计划、多端口、固定帧/状态/延迟/尾部、快照与取消 | 按AR-14～17及引用G2要求验收 |
| R6 | Python runner、真实算法、质量/性能、完整工作台与打包 | 全部累计必需项通过后交付最终结果 |

阶段顺序用于组织工作，不允许把已知产品失败隐藏到后续阶段；外部条件不足时可以推进无依赖切片，但不能给未验证阶段标passed。独立数据与评测线保持原有归属；需要集成时核对实际接口和产物，不重复覆盖其实现。

## 3. 不重复确认的工作

常规接口设计、局部重构、测试补齐、回归修复、兼容迁移、阶段推进和自审发现缺陷后的修复均已授权。每片完成后自行选择下一条未完成行为并继续，不以完成一份计划、一项测试、一个阶段或达到某个测试数量作为结束整个任务的理由。

循环固定为：Define → 真实Red → 最小实现 → 同目标Green → Refactor → 受影响累积回归 → 独立验收 → 证据 → 下一片。测试断言实际值、状态、身份及产物；保存真实失败和修复结果，不删除断言、不放宽阈值、不跳过必需项、不伪造golden或桌面证据。

三轮同根因无进展时，缩小重现、检查接口与设计假设、记录ADR后继续诊断。阶段结束运行该阶段累计集合和当前构型矩阵，不在没有新变化时反复执行同一全量套件。冻结源码后生成对应build/CTest/故障传播/桌面证据，按真实逐项结果汇总。

用户途中询问进展或要求Review属于任务中的沟通，不自动取消持续开发范围；用户明确暂停、取消或改变目标时按新指令处理。上下文压缩不重启任务；会话中断时持久化源码/证据/下一条Red，恢复后核实并接续。

## 4. 权限及阻塞边界

本授权不替代工具权限审批。必要的外部权限、设备、数据、许可或凭据确实缺少时，准确记录缺项、影响、尝试和恢复条件；继续其他可执行工作。只有缺少必要授权/资源/输入且没有可行独立工作时，才交接阻塞；不能把阻塞或测试缺失当完成。

不自动提交、推送、发布或购买，不覆盖用户工程/音频及无关改动，不修改其他仓库。保持进度沟通和可恢复记录；不承诺会话被关闭后仍会自动执行。

## 5. 最终完成条件

只有以下事实全部成立，才能宣布“全部重构完成”：

1. R0～R6所有必需项累计通过，AR-01～20的全部110个字母子用例逐项有实际runner、执行结果和所需证据。
2. 各阶段引用的原平台G0～G6与NED必需要求按原文通过；R6的真实算法、质量/设备/桌面/Release与打包等必需项不得被纯单测替代。
3. 所有仍适用的Review缺陷已关闭，生产GUI/CLI调用真实实现；纯算法和应用层依赖边界及插件扩展方式得到行为/独立构建证明。
4. 当前源码与最终二进制、环境、日志、JUnit、示例、运行产物、桌面及质量证据可对应；所有必需项无failed/skipped/not_run/timeout/not_verified残留。
5. 交付可运行编辑器/CLI、独立算法库与插件示例、构建/验证命令、最终报告和准确状态；维护development_status与build/reports中的入口。

R0～R4通过只代表基本解耦；自动化全绿、阶段代码写完或外部证据待补均不代表全部重构完成。持续工作直到上述条件满足，或按第4节作真实阻塞交接。
