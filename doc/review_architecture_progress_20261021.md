## 发现

### F1 / P2：多输出非有限数值错误定位到错误端口

位置：`libs/audio_juce_backend/NativeNodeAudioProcessor.cpp` 第 246～252 行。

输出扫描已经遍历全部输出通道，但发现 NaN/Inf 后仍固定使用 `output_port_id_`，该字段是描述中的第一个输出端口。新命名端口接口因此丢失了故障输出归属。

独立探针创建一个 input/main/side 双输出节点，main 全为有限值，仅 side 写 NaN。实际诊断为 `output_non_finite, node=bad-second-output, actual_port=main`，正确端口应为 side；探针退出码 42。数值拦截有效，但错误标记会指向健康端口，影响多输出排错及 AR-07.e/AR-14 的定位契约。

证据：`named-port-probe.json`、`named-port-probe.log`、`probe.cpp`。探针链接当前生产库，不修改原有测试。修复应从扁平输出通道反查命名端口，保留回调零分配，不在错误中伪造通道到端口的关系。补第一/第二输出、不同通道的 NaN/±Inf 及重新 prepare 后恢复用例。

### F2 / 接续停点：双独立源仍未实现，当前不是全绿候选

`RunService.cpp` 在发现第二个 source 时返回 `graph_shape_unsupported`；`NativePlan.cpp` 亦要求恰好一个 source 和 sink。T25 已加入真实双 WAV 测试，已有构建成功记录，但中断前目录只有任务卡和 red-build，不能把“构建成功”当作行为 Red 或 Green。

本次实际运行该用例，首个 host=1/normal 场景在 `test_native_node_contracts.cpp:1082` 失败，诊断为 `A G1 run requires exactly one audio source`。现在已有真实行为 Red，可从此接续，不必重新编造失败。

这是明确声明的 R5 未完成能力，不是 T24 已承诺完成的功能退化。应贯通资源物化、纯计划、后端源绑定和重放；不能仅删除两处数量检查，或把一份缓冲重复供给两路。

### F3 / 交接风险：状态入口和历史证据需明确区分

状态文档顶部仍是 T24 的“下一条 Red T25”，旧标题日期为 10-20。实际已有 T25 测试和构建；本次又补充了真实失败观察和 F1。后续应维护一个精简的当前入口，历史日志保留但不再将每个历史“下一条”当作待执行任务。

M20 全量矩阵绑定旧源码；T21～T24 是随后变化的定向证据。用旧全量数字替代当前累计通过会失真。本次没有发现阶段汇总把这些缺项标为正式 passed；问题是接手时容易误读，需通过新入口纠正。
