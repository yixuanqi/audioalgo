# 查看运行日志

运行工程后，底部 **Run logs** 显示本次运行的节点、精确版本和请求身份。可按节点与级别组合筛选；切回 **All nodes / All levels** 会恢复仍保留的隐藏日志。**Copy logs** 复制选中文本，没有选中时复制当前筛选后的保留尾部。

已保存工程可点击 **History**，从时间、请求和 revision 列表选择先前有日志的运行。旁边会标明 **Archived Run**。选择 **Current Run** 返回当前运行日志。浏览旧日志不会改变工程、当前计算结果或试听目标，也不会重新执行旧代码。

列表展示当前工程目录中最近至多 128 份有日志的运行；没有用户日志的运行暂不列入。历史档案在后台读取，正在计算时会等待现有后台工作完成。New、Open、新 Run 和关闭会撤销旧读取的显示资格。

原生日志中的 NUL 显示为 `\0`，其他非换行/制表的控制字符显示为 `\xNN`，后续文本仍可查看和复制。原始流保留完整字节；事件档案对含 NUL 的消息用 `text_encoding: "utf8-base64"` 及 `text_utf8_base64` 保留原始 UTF-8，`text` 是可读回退文本。

界面和历史浏览均展示有界尾部。截断提示与原始流位置保留在日志中，不能把尾部当作完整输出；需要完整文本时使用显示的原始日志文件。计算失败、取消和超限档案与成功结果分开保留。

当前自动化范围及尚未验证的桌面、完整专项要求见 [唯一当前摘要](development_status.md)。

原生节点的 Inspector 和节点库条目说明该版本是否提供用户日志；旧 v1 节点没有日志扩展时显示 **User logs: unavailable in this version.**。

原生原始流旁的 `.summary.json` 保留最多64KiB的完整UTF-8尾部，NUL按Base64原字节携带。尾部丢弃、原始文件已保存字节和SDK队满/非法消息计数分别记录；尾部淘汰不截断原始流。界面尾部预算仍为合计256KiB。
