# 算法与编辑器分离重构测试及通过准则

## 1. 使用范围与通过语义

与[重构开发方案](plan_architecture_refactor.md)、[重构 Agent 规程](agent_loop_architecture_refactor.md)配套。本文是待实现验收契约；ID 出现在文档不表示测试已经注册、执行或通过。

AR-01～AR-20 的每个字母子用例都为必需项。一个父 ID 只有所有子用例、引用的原平台验收和必需证据全部通过才为 passed。passed、failed、not_run、not_verified、blocked、skipped、timeout 分开记录；后六种不能通过对应阶段。编译失败、配置失败、测试失败、环境受限不得混称。

“基本解耦完成”要求 R0～R4 累积要求全部通过；“本重构计划完成”要求 R0～R6 全部通过；“平台首版完成”还须原 G0～G6、NED-01～14 的全部必需子用例通过。可以报告已验证子集，不能用基本解耦通过宣称整个平台完成。外部数据/桌面受限时保留未通过状态，同时继续独立工作。

原[主验收](testing_audio_pipeline_editor.md)和[交互专项验收](testing_editor_node_interaction.md)继续有效；本文不替换或放宽其阈值。引用原测试 ID 时包括该 ID 的全部必需子用例，而非仅同名前缀的一条测试。

## 3. 运行器、数据与独立 oracle

### 3.1 测试分层

- pure：core/算法、目录、模型、controller；无需 JUCE 消息环境、窗口、设备和网络。
- native integration：真实 JUCE backend、文件产物、CLI；可初始化必要消息环境，但不依赖项目 View 和设备。
- component：真实 JUCE 参数面板、事件绑定；明确使用消息环境，不能标为 pure。
- desktop：通过允许的桌面工具执行真实编辑交互，读取本次输出并关联截图。
- build/consumer：在独立构建目录验证依赖、可选配置与导出库消费。
- infrastructure：使用受控 fixture 验证验证器失败传播、inventory 与证据校验。

建议拆分对应 CTest targets/labels；目标名称可据实际工程调整，但需在版本化 manifest 中精确映射。默认单元超时10秒、原生集成60秒、Python/算法180秒；构建与长文件专项单列合理预算并记录依据，不扩大原有取消和性能阈值。

### 3.2 固定输入

复用 F01/F02/F03 等原主验收配方，使用固定 seed、1/2/4通道、16/48 kHz、互异通道、静音、脉冲、非整帧边界。Gain 至少覆盖长度0/1/479/480/481/511/512/513/16037，-60/-6/0/+6/+12 dB；零长度按原契约接受或明确诊断，禁止崩溃或伪造帧数。

Legacy 工程在 R0 从当前 `examples/gain_demo/gain_demo.aaproj` 及已有专项工程制成只读 fixture，保存相对路径、SHA-256、节点/参数/连接/布局与 oracle 配方；不得覆盖用户工程或把迁移后文件重新批准为迁移前基线。输出以独立数学关系验证，不把旧输出字节等同天然真值。

Gain、直通、ChannelSwap 逐样本使用 float64 独立 oracle，满足 `abs(actual-expected) <= 2e-6 + 1e-5*abs(expected)`；帧数、通道 ID、顺序、有效区间精确相同。PCM16、Speex、Python、STFT、质量与性能全部沿用原主验收第2、6、7节。GUI/CLI 一致还须各自符合 oracle，不能只比较两份同源错误输出。

并发/回填测试采用可控 barrier/latch、显式任务完成顺序和确定性 fake service，避免靠随机 sleep 竞态。至少再以真实原生任务验证一次事件接收与产物发布链。fake 用于调度，不能替代真实算法输出。

## 4. 基础设施与运行身份

### AR-01 基线与回归保护（R0）

- a：记录当前源码、工具、依赖、全部配置与 CTest inventory；实际构建并运行 Debug/headless 受影响集合，分别列明失败/跳过/未执行，不引用旧数量认定当前通过。
- b：冻结只读 Legacy 工程/输入及解析 oracle；本次读取不改变 fixture/输入 hash，CLI 产物与工程/run ID 可关联。
- c：所有现有 CORE/DSP/GRAPH/IO/PRJ/E2E 和 NED 注册有旧→新映射；拆 target 不丢失子用例，不将桌面要求改为可选；受影响旧用例实际执行。
- d：修改后重建对应可执行文件并记录源码、binary hash、配置与时间；应用锁定旧 exe 时可用已授权独立构建输出，旧进程截图不能充当新源码验证。

AR-01.a 的“建立基线”允许准确记录预先存在的失败；这只证明基线流程完成，不将其引用的产品测试判为 passed。任何重构新引入失败都阻止当前切片完成；阶段引用的必需原验收必须实际通过。

### AR-02 验证器拒绝假通过（R0，后续持续回归）

- a：版本化 manifest 精确列出本文全部字母子用例、阶段、层次、runner、测试名和证据要求，并绑定本文内容 hash；漏一个、重复、非法阶段或文档 hash 不匹配均非零。
- b：零测试、缺一个注册、存在注册但未执行、错误配置/二进制、进程崩溃均非零；不能仅由测试名或总退出码推断逐用例结果。
- c：受控断言失败/skip/timeout 均使子用例与阶段非 passed；解析逐用例 JUnit/CTest XML 并核对实际执行数量。
- d：缺失/过期/错误 hash 的桌面、运行产物、构建或独立审查证据为 not_verified 且最终非零；仅自填 passed JSON 不得通过。
- e：原主 Gate 显式覆盖 QUAL-01～03、构建矩阵、桌面与设备要求，漏收任一即非零；测试文档章节组织变化不能使质量条目消失。
- f：每次写独立时间戳报告，含命令参数数组、cwd、UTC时间、退出码、日志/产物hash、逐用例状态与理由；失败不覆盖上次成功或本次原始日志。
- g：故意失败探针在临时独立工程/fixture 中实际失败，验证失败传到 Gate；恢复后正常 inventory 无探针残留。合成基础设施测试与真实产品验收清晰分开。

### AR-03 完整运行身份与结果权限（R0）

- a：工程 A 运行未结束，打开相同 revision 的工程 B；A 成功晚到后，B 的波形、播放文件、状态和当前结果均不改变。
- b：同一场景让 A 失败/进度/取消事件晚到，所有当前显示与状态同样不改变；错误分支必须先校验身份。
- c：同工程同 revision 发起两次请求，后请求先完成，再投递旧事件；只有最新有效请求更新当前结果。
- d：New/Open 增加 session_epoch，重开同 project_id/revision 也不能复用旧接收权限。
- e：参数/拓扑修改、Undo/Redo 创建新计算 revision；旧完成不得恢复当前结果资格，历史结果准确标过期。
- f：有效身份的成功/失败/进度可正常展示；旧成功仍可作为正确归属的历史产物保留，不能被错误标为当前。
- g：真实原生后台运行与消息线程回填贯通，事件携带 project_id、epoch、request_id、revision；run_id 与请求对应且唯一，身份在排队前确定，日志/manifest 可追踪。

## 5. 算法库、SDK 与原生执行

### AR-04 算法库独立消费（a～d：R1；e：R4）

- a：core/algorithms 公共头文件与链接依赖不含 NodeSDK、ProjectModel、JUCE、View；独立消费者实际编译调用 Gain。
- b：全新构建目录只构建算法/core及其测试时，不获取 JUCE、不查找 Python、不初始化窗口/设备；无已缓存 JUCE 路径掩盖依赖。
- c：算法测试是独立 pure target，不链接含 GUI 的大测试程序；在禁用 editor/Python/Speex 配置中实际执行且非零测试。
- d：prepare/process/reset 的公开契约、借用视图有效期和配置错误有行为测试；算法无需节点 ID、JSON 或工程路径即可使用。
- e：安装到临时前缀后，在独立工程通过导出 CMake target 编译并运行 Gain/ChannelSwap；导出 include/link 不依赖源码树绝对路径，安装后消费者禁网且成功。

### AR-05 Gain 单一数值实现（R1）

- a：独立算法便捷接口与 block API 对固定长度/通道/增益矩阵满足数学 oracle，输入不变。
- b：NodeAdapter 调同一内核，真实 JUCE wrapper、CLI 和实际 GUI 运行各自满足 oracle；样本、有效区间和输入 hash 正确。
- c：缺省、边界、越界、错误类型、NaN/Inf 参数/输入按原契约明确接受或拒绝；UI、controller、runtime 无校验绕过。
- d：依赖与生产调用链证明生产通过 algorithms 库，backend/View 无第二份 Gain 运算；在受控隔离 mutation 中改变算法内核能使独立/节点/运行 oracle 同时捕获错误，随后完整恢复并重跑。
- e：旧 Gain 工程保存重开后重新执行及播放数据路径正确；去掉旧 factory 路径后完整回归，无双注册或选择到旧实现。

### AR-06 描述/工厂注册与插件边界（R1）

- a：一次注册原子加入描述和匹配执行工厂；重复类型/版本冲突、空工厂、非法端口失败后目录和工厂均不改变。
- b：默认值类型、范围、enum稳定值、参数重复、格式与能力约束不合法时拒绝，诊断指出具体字段。
- c：两个同类型实例不共享算法状态，工厂构造失败返回节点可定位诊断，无崩溃或半准备计划。
- d：View/app 通过只读 catalog 使用元数据，不能调用工厂；SDK/backend 不链接 builtin 插件或具体算法；GUI/CLI 装配的内置目录一致。
- e：未知执行方式、缺 backend、未支持帧/端口能力明确 unavailable/unsupported，不能注册为可运行后静默直通。
- f：通用描述和工厂接口支持新类型加入，不要求修改 SDK 的算法枚举或算法名分支；插件与通用类型扩展范围有实际变更清单。

### AR-07 通用 JUCE wrapper（R1）

- a：wrapper 接受 SDK 原生实例，Gain 与一个测试处理器通过同一代码路径执行，backend 不认识具体算法 type_id。
- b：1/2/4通道互异输入、尾部不足块、host块1/127/256/480/512/1024，已声明 N入/N出能力时计数和音频正确；尚未支持的能力明确拒绝。
- c：prepare 只在计划准备执行，跨块保持同实例；新运行/reset 不复用不相容状态，实例释放顺序可观测。
- d：处理回调不申请动态内存、做文件 I/O、启动 Python、解析 JSON 或复制整段音频；在完成 prepare/预热后的 wrapper+节点路径使用受控分配计数及I/O/线程探针验证，排除测试自身分配并记录范围。不据此宣称整个系统实时。
- e：SDK错误/可恢复异常携带节点和端口上下文，经统一诊断返回；无效输出/无进展不能形成静默成功。旧 JuceProcessorRegistry 算法路径迁移后不存在生产回退。

## 6. 应用控制、描述驱动界面与持久化

### AR-08 编辑命令与历史（R2）

- a：通过 controller 在无窗口测试中添加、连接、断开、插入、删除，原子性/失败不变/分支保留满足既有 NED。
- b：SetParameter 合法修改产生一个新计算 revision、可追踪实际值、dirty和过期状态；非法修改不改变模型/历史/有效当前结果。
- c：参数修改可撤销重做，一次滑块手势合并为一条历史，取消手势不遗留部分参数；撤销重做 revision 单调递增。
- d：MoveNodeLayout 只修改布局与保存状态，不改变计算 revision、不启动任务；参数/拓扑修改才使计算结果过期。
- e：新增命令清除 redo，失败命令保留 redo；New/Open 清空历史、旧文件选择器/拖放/选择状态，不把后完成的操作写入新工程。
- f：拓扑与参数/布局交错操作后，撤销目标行为符合记录的命令契约；不误吞后续不属于目标命令的状态，不保存 JUCE 对象。
- g：controller 与 runtime 使用共用描述校验规则，绕过控件发非法参数/连线同样拒绝，诊断含 node/parameter/port ID。

### AR-09 无控件应用层与生命周期（R2）

- a：application/run_api 公共接口不包含 Component/Slider/AudioProcessorGraph 等控件和具体 backend 类型；application纯测试不链接JUCE实现。Open/Save和资源/播放经无JUCE接口注入，独立纯测试构建通过。
- b：View 通过意图/命令和只读展示快照工作，不持可变 ProjectModel/节点实例；行为测试证明所有修改经过 controller 校验/历史。
- c：展示快照不含失效可变指针；删除节点、替换工程、异步任务晚到和关闭 View 不悬空访问。
- d：View 解除订阅后仍存活的 service 不回调已销毁 View；宿主销毁按取消/回收/销毁依赖顺序完成，无遗留 worker。
- e：消息线程投递在 UI 适配实现，纯 controller 测试不用 JUCE；耗时工作/I/O 不在消息线程，完整心跳预算沿用 PERF-01。

### AR-10 自动参数面板（R3）

- a：bool/int/float/enum/string/path 由描述生成，标签/默认值/范围/步长/单位/help 与描述一致；enum 保存稳定值，不保存显示下标。
- b：控件绑定 node_id+parameter_id，经 SetParameter 修改正确实例；切换节点/重建面板不触发误写，不把上个节点值带到下个节点。
- c：数值边界、非法字符串、未知enum、缺路径/资源均有具体诊断；禁用控件或绕过 UI 都不能越过后端校验。
- d：reset-to-default 提交同一命令/历史路径，Undo/Redo 同步控件与模型，单位与默认值不在 View 重复硬编码。
- e：支持的 visible/enabled 声明规则按参数更新，不执行任意脚本；未知结构字段只读且说明原因，保存不丢值。
- f：通用节点摘要来自 descriptor；新增算法元数据变化无需增加画布 type_id 判断，完整tooltip保留。
- g：实际组件控件改变真实执行/报告：使用测试插件的 enabled(bool)、repeat(int)、scale(float)、polarity(enum)、tag(string)、coefficient(resource path)。参考公式 `y=x*(enabled?repeat*scale*polarity*coefficient:1)`，polarity为±1，系数资源固定；tag只影响报告，不伪装成DSP参数。各字段有独立预设期望和资源hash，禁止只断言数值“发生变化”。
- h：至少实际桌面完成 Gain 调参、另一个描述驱动节点参数编辑、运行和错误恢复；GUI产物通过数值oracle，鼠标/键盘输入、截图与项目/run ID对应。

### AR-11 View 分离与真实交互（R3）

- a：Main.cpp 仅组装窗口/服务和生命周期；画布、库、参数、波形、运行状态形成独立组件；以职责/依赖审查判定，不用任意行数作通过阈值。
- b：真实桌面完成库拖入、端口连接、选线断开、处理节点插入/删除、Undo/Redo；模型和视图一致，原 NED 全部相关子用例仍成立。
- c：New→Open→调参→Run→保存→重开→重跑，输出归属正确；输入文件不变，GUI/CLI同快照均满足oracle。
- d：100/150/200% DPI、中文与空格路径、窗口缩放、长标签/tooltip符合原 UI-07/NED；截图来自本次真实应用，不生成假界面。
- e：播放/暂停、设备不可用诊断与实际输出数据路径保持正确；真实听评和设备证据按主验收记录，无设备不能报告最终播放验收通过。

### AR-12 新算法扩展证明（R4）

- a：加入全新 namespaced ChannelSwap 算法/描述/adapter/注册/示例；仅允许插件、算法、注册、构建、测试和示例范围变更。
- b：记录接入前后通用 View/参数表单/compiler/scheduler 文件清单与内容hash，确认无产品修改；无 Git 时以实际文件manifest对比，新建通用文件也纳入审查，不能仅比较已知旧文件。
- c：双通道互异固定信号交换精确符合解析oracle；单/四通道支持或拒绝按描述一致，错误参数、两实例/reset/尾部符合声明。
- d：在实际 GUI 从节点库添加并调参/连接执行，CLI同工程执行，GUI/CLI均符合oracle；显示端口/参数不增加类型特判。

## 8. 证据、注册和汇总约定

以下文件/命令为后续待实现契约，本文创建时不视为存在：

- `tests/architecture_refactor_manifest.json`：精确展开全部AR子用例，含stage、required、layer、runner、test_names、evidence_requirements、原ID映射。
- `scripts/verify_architecture_refactor.py`：从inventory执行并核对本阶段及前序所需项，审查真实产物/证据；支持`--stage R0`至`R6`及可选`--pure`开发视图。
- `tests/unit/`下按实际模块组织新增回归；`tests/integration/`的consumer/backend/CLI用例；`tests/gui/`组件与桌面步骤。先检查已有测试并复用，避免同一行为复制多份镜像测试。

`AR-xx.a`是验收ID；一个子用例可映射多个精确测试名/证据任务，所有映射项通过才完成。一个测试覆盖多个子用例时manifest明确共享事实，仍需逐子用例判定。仅有case标签或父ID前缀不算注册完整。

报告位于 `build/reports/architecture_refactor/<UTC timestamp>/`，切片原始证据位于 `build/reports/loops/RFxxxx/`。每份报告含完整源码manifest/hash、产品相关源码与binary hash、验收文档hash、环境、命令、逐项执行结果、独立证据及限制。文档变更时重新绑定验收hash；产品代码变化后不能复用受影响旧证据。纯文档变化复用产品证据需明确范围、产品内容hash一致和理由，不能自动放行。

桌面记录至少包括实际操作步骤/方式、时间、OS/DPI、物理/逻辑窗口尺寸、binary与源码hash、截图/录屏hash、project/request/run/revision关联。需实际读取本次音频并对oracle验算；截图只证明显示状态。当前工具无法操作桌面时如实not_verified，不运行历史未授权自动化或编造截图。

`--pure`只报告不依赖桌面的开发子集，必须明确`scope=development_subset`、整体不宣称阶段passed；对尚未完成的阶段可输出非零，但不能通过缩小筛选冒充阶段通过。无论是否提供该选项，正式阶段验证始终检查完整累计必需集合。

## 9. 明确拒绝的“通过”方式

禁止放宽数值/时间阈值、删除断言、调整期望迎合当前输出、把必需项改可选、删除旧测试或fixture、批准自生成golden、以测试名替代执行、以旧exe截图代替当前源码、以同源输出互比代替独立oracle、以headless绿色代替桌面/设备/真实数据。合理契约改变先写ADR及独立依据，再同步验收；失败仍需真实保留。
