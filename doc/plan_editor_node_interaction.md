# 编辑器文字显示、节点拖放与连线插入专项开发方案

## 1. 任务、授权与完成边界

本专项落实用户提出的乱码、左侧算法 Node 拖到 canvas、Node 插入问题。本文是[平台开发方案](plan_audio_pipeline_editor_juce.md)第 8 节的增量设计，配合[专项验收准则](testing_editor_node_interaction.md)和[专项 Agent 规程](agent_loop_editor_node_interaction.md)实施。仍须遵守平台测试文档与通用 Agent 规程。

2026-10-18：当前代码任务优先按[重构方案](plan_architecture_refactor.md)的R0～R6迁移算法/控制层/界面；本专项的交互语义、NED全部子用例与真实桌面要求作为回归和最终验收保留。旧NI顺序用于恢复专项缺项，不能阻止独立后端重构；改动本专项组件仍须先读并运行相关验收。

本次文档交付不包含产品代码修改。后续开发 Agent 获得的授权是：在当前仓库按本文直接实施、测试、自验证和自迭代，常规设计、文件拆分、构建及修复无需中途确认；仅实际工具权限或必要外部输入不足时如实说明，并继续不受影响的工作。不自动提交、推送、发布、购买许可，不覆盖用户音频和无关修改。

专项完成须同时具备：

1. 文字正确解码，标题、摘要、端口不叠字，中文与目标 DPI 可用。
2. 从节点库点击或拖放创建节点，落点正确、不重复创建、不静默遮挡已有节点。
3. 未完成的图可以逐步接线；非法拓扑拒绝；Run 仍执行严格完整性检查。
4. 节点库中的兼容处理节点拖到连线上，能预览并原子替换该边；已有未连接节点也可拖入连线。
5. 断线、删除、选中、移动、Output 重建、保存重开及相关拓扑撤销重做保持一致。
6. 真实 GUI 操作产生的图可运行，输出通过独立数学 oracle，专项全部必需检查有证据。

不借本专项扩展 Python runner、Speex、多源混音、多输出运行、任意格式转换或通用图形算法编程。专项完成不等于 G0/G1 或整个平台全部完成。

## 2. 已核实基线与根因

2026-10-17 的只读分析已检查源文件、历史截图及状态文档；现有 Debug 二进制的非 GUI 检查 16/16 通过，未重新编译，也未进行新的桌面验收。恢复开发时必须重新验证当前源码和构建，不能照抄这个数字。

| 现象 | 已核实实现与根因 | 证据入口 |
|---|---|---|
| Gain 的 6.0 dB 与 IN、Output 的 Audio output 与 IN 混在一起 | 摘要矩形占节点相对 y=48～70，输入标签占 y=57～71，均从 x=12 开始 | `apps/editor/Main.cpp` 的 `paint_node`、`input_port` |
| 历史 File source…、分隔符出现异常字符 | 非 ASCII 的 UTF-8 字面量曾隐式进入 JUCE ASCII 构造函数；当前已有 `utf8_literal/fromUTF8` 修复 | `build/reports/loops/L0009/loop.md` 及前后截图 |
| 左侧拖动无效 | 条目是绑定 onClick 的 TextButton；没有库拖拽源、DragAndDropContainer 或画布 DragAndDropTarget | `EditorComponent`、`GraphCanvas` |
| 新节点挡住 Output，点击选错对象 | `next_position` 只按节点数计算位置，无碰撞检测；绘制与命中都正序，视觉顶层与命中优先级相反 | `Main.cpp`；`build/reports/loops/L0012/loop.md` |
| 空白图无法一条一条接线 | `connect_to` 添加一条边后调用完整 `validate_project`，其他必需输入未接就使此次接线回滚 | `Main.cpp`；`libs/audio_project/ProjectModel.cpp` |
| 拖到线上没有插入，已有边无法替换 | 无边命中、断线、拆边插入事务；普通连线只追加，目标已有输入会被判重复 | `GraphCanvas::connect_to/paint_connections` |
| 删除再添加 Output 后运行仍失败 | 删除清空 `selected_output_node_id`，创建 Output 未恢复；backend 要求其指向唯一 sink | `Main.cpp`；`libs/audio_juce_backend/JuceGraph.cpp` |

现有 GUI 连线是点击输出后再点击输入；`mouseDrag` 只处理节点移动，`mouseUp` 只清理移动状态。已有“添加 Gain 后接分支”的历史成功记录没有验证串联插入、拖放或从零搭图。

当前源码未发现独立编辑 Controller/Command 模块。`scripts/verify_editor_interaction.py`、`tests/editor_interaction_manifest.json` 和本专项测试均是待实现交付，不能当成现有工具使用。主 `verify_gate.py` 目前扫描主验收表并按测试名前缀汇总 ID，不足以证明本专项全部子用例和桌面行为通过。

## 3. 实施架构与最小修改范围

### 3.1 模型、命令、视图的职责

保持 `ProjectModel` 为唯一工程真相，JUCE graph 仍仅是运行投影。最小编辑服务不依赖 JUCE 控件，负责 AddNode、Connect、Disconnect、InsertNodeOnConnection、DeleteNode 和对应拓扑历史。View 只负责输入状态、坐标变换、预览、绘制及提示；不直接零散修改节点/连接 vector。

建议新增 `libs/audio_editor_application/` 或在现有项目层建立同等边界；具体文件名和 target 可按最小依赖调整并记录，不为未来工作搭建空框架。算法库不新增 GUI、编辑服务或工程模型依赖。

领域命令接收值类型：节点 type/ID、精确端口 ID、连接的四元组、模型坐标及必要的期望工程 epoch/revision。结果含成功状态、变化摘要及结构化诊断（code、node_id、port_id，必要时连接端点）。UI 不通过错误字符串决定控制流。

命令先构造候选状态并校验，再一次提交。拒绝、取消、预览不得改变工程、dirty、计算 revision、布局和历史栈。允许为最小实现保存值类型的 before/after 状态，不保存 JUCE 对象、运行指针或悬空引用。

### 3.2 两类校验，保留严格运行约束

| 校验层 | 必须检查 | 允许的中间状态 |
|---|---|---|
| 编辑结构校验 | ID 唯一、节点/端口存在、方向、类型、输入基数、重复边、自连、DAG；本次参数类型与范围 | 未连接的必需输入、尚未选择资源、尚无 Source/Output |
| Run 校验 | 编辑结构全部规则，加必需输入、必需资源、可用处理器、选定输出、当前 backend 支持的图形状和格式 | 不允许以不完整图执行 |

为兼容现有调用，可保持 `validate_project` 的严格语义，抽取公用结构校验供编辑命令使用，或采用显式且无歧义的校验模式。不得修改现有 GRAPH-01 对缺输入的拒绝断言，使其不再覆盖 Run 完整性。

当前运行路径仍是一源一 sink、每节点至多一个音频输入/输出的已实现子集。对第二个 Source/Output 的添加应在提交前按已实现能力返回具体诊断；不能让 View 对每个算法名字分支。可用描述的 source/sink 能力或组合根提供的资源创建策略表达限制。多端口测试 fixture 只证明编辑层与选择机制，不能据此声明 backend 已支持多端口运行。

### 3.3 revision、dirty 与历史

- 成功添加、接线、断线、插入、删除：每个用户命令只增加一次计算 revision，并标记未保存。
- 移动、层级/选择、预览：不增加计算 revision；持久化布局的移动应标记布局未保存。选中与悬停不标记工程修改。
- 本专项新增拓扑命令须支持一次撤销/重做；每次撤销/重做产生新的单调递增计算 revision，不能恢复旧 revision。
- 失败命令不入历史；撤销后发起新拓扑命令清空 redo 分支。插入的创建节点、删旧边、加新边只有一个历史项。
- 纯移动可使用独立布局历史；其撤销不增加计算 revision。不要求在本专项实现完整参数历史，因此不可单独据此宣称主 PRJ-02 全部通过。
- Open/New 改变工程 epoch 并清理拖拽、待连接、选择、异步资源选择和历史的旧工程上下文。旧回调不能修改新工程。

## 4. 文字与节点布局

统一项目 UTF-8 到 JUCE String 的转换边界；保留 `/utf-8`，不更改 Windows 全局代码页。项目路径继续采用 UTF-8 与 filesystem Unicode 路径转换，不退回窄字符本地代码页。

节点使用互不重叠的标题区、摘要区、端口区，所有绘制和命中共享同一份几何结果。节点尺寸可随端口行数增长；不能只改文字位置而让端口视觉位置与点击热区分离。端口显示描述中的 ID/名称，不把所有端口固定画成一个 IN/OUT。长名称限制在节点内容区，必要时省略并给完整提示；节点标题矩形不得伸入相邻节点。

中文测试使用实际工程名、WAV 文件名和描述标题；检查底层文本及最终渲染。字体缺字与编码错误分开定位：字符值正确但显示方框时检查字体 fallback；字符值已错误时检查解码边界。不为颜色/装饰样式编写镜像测试。

## 5. 放置、命中和拖拽状态

### 5.1 放置和命中

点击添加：在当前画布可见工作区寻找有界数量的空位，避开节点及其外扩 8 个逻辑像素的保留区。拖放添加：默认使用鼠标相对节点中心的锚点；预览与提交使用同一锚点。若落点碰撞，展示最近合法位置；确定的候选搜索顺序和上限写入实现说明。没有合法可见位置时拒绝并提示扩大窗口/腾出空间，禁止悄悄放到不可见区域。

坐标从 JUCE 事件转换至 canvas 局部逻辑坐标，再转换到模型坐标；不手动乘系统 DPI。当前没有缩放/滚动不要求提前实现，但必须集中坐标变换入口，避免将屏幕/父控件坐标直接写入模型。

绘制从底到顶，命中从顶到底；节点/端口优先于背后的连线。重叠节点用明确顺序决定顶层；创建后选中新节点并显示 Inspector。选择、命中与层级不得意外改变计算结果。

### 5.2 节点库拖放

节点库遍历 registry 描述生成条目，payload 只携带版本化操作类型和 type_id，不携带裸指针或用户代码。点击与拖拽共享编辑命令，但只有超过 6 个逻辑像素的移动才进入拖拽；拖拽结束抑制该手势对应的按钮点击，确保仅创建一次。

使用锁定 JUCE 源码中的 `DragAndDropContainer/DragAndDropTarget` 或等价已验证接口。画布在 enter/move/exit/drop 中更新预览；释放在画布外、Esc、失去有效源、切换工程、关闭视图均清理预览并保持工程不变。

File source 在有效落点后进入异步资源选择，成功才提交；保存 type、模型落点及工程 epoch，回调重新检查能力、落点与目标工程。取消不留空节点；工程已切换或目标边已失效则取消旧操作并提示，不误插入新工程。

### 5.3 端口连线与断线

保留点击输出→点击输入，并补齐按下输出→拖到输入→松开。两种方式调用同一 Connect 命令，按精确端口 ID 操作。至少区分 Idle、MovingNode、Connecting、LibraryDrag、PendingResource 状态，避免一次鼠标事件同时移动节点和接线。

鼠标拖动时更新连接预览，松开只提交一次。Esc/画布外释放清理；非法端口、自连、重复输入、重复边或环返回具体诊断。不能通过静默覆盖现有输入来“修好”连接。提供可发现的边选择和 Delete/右键断开入口，断开后允许继续编辑，Run 应指出缺失输入。

## 6. 在线上插入节点

### 6.1 目标边、端口匹配与反馈

对实际绘制的贝塞尔路径做距离命中，命中阈值固定为 8 个画布逻辑像素；测试覆盖明显内侧与明显外侧，并定义边界取 <=。命中多个路径时选距离最近者，同距用稳定顺序；节点覆盖区不触发背后边的插入。预览高亮唯一目标边和最终节点位置。

对旧边 `(A,p) → (B,q)`，按描述找候选 `(new.in,new.out)`，要求 `A.p` 与 `new.in`、`new.out` 与 `B.q` 类型相容，方向和基数合法。当前不做隐式转换、不按 Gain 名称特判。没有兼容组合则明确拒绝；唯一组合直接使用；多组合显示端口选择，取消不修改图。若仍有其他必需输入未接，作为合法待补全编辑状态保留并提示，Run 继续拒绝。

### 6.2 原子提交

库拖入连线：在候选模型中创建新节点、移除且仅移除选中的旧边、加入两条新边，执行编辑结构校验，再一次提交。其他分支、节点、参数、资源和选定输出保持不变。旧边 ID/四元组及工程 epoch/revision 发生变化时重新验证目标；不能继续使用悬空对象。

已有节点拖入连线：首版仅允许当前没有入边/出边的处理节点；连接中的节点明确拒绝自动重接，保持它原有拓扑和拖拽前布局。普通移动到空白处仍正常。来源为 Source/Sink 或不相容节点时，不因经过某条线而删除原连线。

提交失败、用户取消端口选择、按 Esc、异步失效时，恢复拖拽前状态。已有节点的移动在手势期间仅预览，落到空白处提交布局，落到合法边提交一个插入事务。失败不留下半个节点、单边或新的历史项。

## 7. Output、工程切换与持久化

删除处理节点时，若节点恰有一条入边和一条出边，先在候选工程中用上游输出端口和下游输入端口建立旁路边，并通过编辑结构校验后再一次提交删除与重连。分支、缺边或不兼容的旁路不自动连接；仍按普通删除清理该节点的边。撤销/重做将删除和旁路作为同一拓扑历史项。

删除 Output 同时删除关联边并清空失效的选定输出；重新创建唯一 sink 时设置 `selected_output_node_id`。读取工程不随意改写用户保存的选择；引用无效时显示诊断，并由明确编辑命令修复。运行仍由 backend 检查单一 sink 和选择一致性。

提供最小 New/清空为新工程入口，使用户不必修改内置 demo 即可从零建图。保存前后 UUID、端口四元组、参数、资源、布局和选定输出一致；不能把相对 WAV 路径丢失当作拖放修复的附带问题忽略。验收使用专用临时演示副本，不覆盖用户工程。关闭/切换工程清理旧拖拽和资源回调；现有运行结果不得伪装成新工程结果。

## 9. 交接与完成判定

每切片更新 `doc/development_status.md` 和 `build/reports/loops/NIxxxx/`。最终更新主状态中的已完成子集、实际阻塞及下一条 Red；专项报告保存 `build/reports/editor_interaction/<时间戳>/`。

专项 NED-01～14 的全部必需子用例通过、桌面/DPI/数值证据齐全且受影响累计回归无失败后，才可声明专项完成。主 G0/G1 缺失的 BLD/LOOP/UI 验收仍独立补齐；不能只注册 NED 名称就把主 Gate 标 passed。完整 Release 包、真实设备播放、G2～G6 仍遵循主方案。

启动提示词见[专项 Agent 规程第 8 节](agent_loop_editor_node_interaction.md#8-启动提示词)。
