# 节点交互专项 Agent TDD 与 Loop Engineering 执行规程

## 1. 执行入口与授权

先读根 `AGENTS.md` 指定的三份主文档，再读[专项方案](plan_editor_node_interaction.md)、[专项验收](testing_editor_node_interaction.md)、本规程和最新 `development_status.md`。本文仅约束节点交互专项的实施顺序与证据，不替代主平台完成定义。

后续 Agent 按 NI0000～NI0006 直接修改和验证当前仓库。常规实现决定自行记录并推进，不在切片/阶段结束要求用户确认或重复授权；不以“方案已生成”“框架已有”“单元全绿”结束代码任务。仅遵守真实工具审批，必要权限/外部资源缺失时说明具体限制并继续独立工作。用户未要求自动提交、推送或发布，不得执行这些操作。

本规程不要求启动定时任务、无限后台循环或子 Agent。Loop Engineering 是可追溯的有限行为迭代。

## 2. 恢复与建立基线

1. 确认仓库根和文件改动。当前分析中 `git status` 返回不是 Git 仓库；恢复时重新检测，不自动初始化 Git，用源码 manifest/hash 代替 commit。
2. 核实当前源码、构建缓存、JUCE 锁定源码、工具路径、测试 inventory 与报告。检查所有建议接口/脚本是否真实存在，未实现的明确标记 planned。
3. 重建当前受影响 targets，执行既有非 GUI 基线。桌面测试须在允许的会话执行并单独记录，不把上次 16/16 或历史截图当作当前结论。
4. 阅读 `L0009` 编码与 `L0012` 重叠记录，复核 `paint_node`、`connect_to`、`next_position`、Output 选择逻辑。编码修复已存在就保留，不为制造 Red 破坏它。
5. 在 `build/reports/loops/NI0000/` 记录环境、源码 hash、实际命令、exit code、当前失败与未验证项。先做专项 verifier 拒绝缺项的最小闭环，随后立即进入产品行为切片，不停留于基础设施建设。

## 3. 每个切片的循环

### Define

一次选择一个可验收行为和最小 NED 子用例，写清初始工程、输入操作、期望模型差异、revision/dirty/历史、界面变化、失败条件及独立 oracle。切片可跨服务/组件/运行层，但不能顺带扩展不相关算法和调度器。

### Red

先写或收紧回归测试，再运行最小目标。保存失败断言、命令和退出码，确认失败属于目标缺陷。缺依赖、无桌面、构建缓存损坏属于 environment_blocked，不冒充 behavior_red。

接口不存在时允许先记录 compile_red；接口可编译后仍须看到行为断言失败，才能证明测试捕获目标缺陷。已有正确行为不强行制造 Red，可使用隔离受控 mutation 验证断言灵敏度，完整恢复并确认无残留。GUI 缺陷用真实输入步骤/截图建立 Red，再配合命令/几何回归。

### Implement → Green

按专项架构最小实现，同一条失败用例重跑直到满足契约。画布只做输入和展示，计算库不受 GUI 污染。运行失败不能通过绕过 validator、容忍重复输入、放宽数值阈值或选择旧成功产物掩盖。

GUI Green 必须补实际桌面观察；模型 Green 不能替代拖放 Green。数值 Green 读取本次生成音频，对独立 float64 oracle 逐样本验证，不仅检查文件存在或 SHA 变化。

### Refactor → Regression

Green 后合并重复路径、收敛命令/坐标/几何入口，保持行为不变。重跑受影响用例和依赖方向上的回归。没有新改动、新失败或未解疑虑时不反复运行同一测试；进入下一切片。

### Evidence → Continue

保存源码及产物 hash、原始日志和图片，更新当前状态、未验证项及下一条 Red。随后继续下一切片，不问“是否继续”。中断后从证据恢复，对变化影响的检查重新运行。

## 4. 必须保持的最小重现

| 缺陷 | 最小重现 | 判定 |
|---|---|---|
| 叠字 | 初始 Gain/Output，查看摘要与 IN 区域 | 文本区域交叠为 Red；修复后区域分离且画面可读 |
| 完整性校验阻断编辑 | File/Gain/Output 都存在但未连接，连接第一条边 | 合法边应提交；Run 在缺第二条边时必须失败 |
| 顶层命中错误 | 两节点矩形相交，点重叠区 | 命中最后绘制的顶层节点 |
| 库拖放缺失/重复 | 从库拖 Gain 到空白区并释放 | 新增恰好一节点；位置等于预览；取消零变化 |
| 插入非原子 | 在 A→B 放入新处理节点 | 一次提交得到 A→N→B；失败恢复全部原状态 |
| Output 选择失效 | 删除唯一 Output 后重建、重连并运行 | 选定输出为新 ID，backend 不报选择不一致 |
| 假通过 | manifest 缺一子用例或桌面证据 | verifier 必须非零，不能只看 CTest 总结 |

测试失败先定位到输入事件、坐标/几何、编辑命令、validator、持久化、运行或报告层，不把所有故障都归因于 JUCE/DPI。

## 5. 三次无进展后的处理

同一根因连续三次迭代没有新证据或改善，必须改变诊断策略：冻结最小重现、减少节点和事件序列，检查上游锁定 JUCE 的鼠标事件、Button 点击及拖放生命周期、SourceDetails 局部坐标、String 编码契约，再验证模型和设计假设。在 `doc/decisions/` 记录调整及验收影响后继续。

不要重复盲点点击、反复改 DPI 倍数、连续扩大边命中范围、放宽阈值或删除失败断言。若桌面工具不可用，继续纯命令/组件/音频工作并保留 desktop not_verified；只有必要资源/授权缺失且无可行独立工作时交接阻塞。

## 6. 报告与状态模板

每个 `build/reports/loops/NIxxxx/loop.md` 至少包含：

```text
切片 / NED 子用例 / 关联主需求：
用户可观察行为：
当前源码 hash、构建配置、可执行文件 hash：
初始工程与输入 / 独立 oracle：
Red 命令、exit code、关键失败断言或桌面步骤：
根因与最小修改：
Green 命令、exit code、通过/失败/跳过/未验证数：
回归命令和结果：
桌面环境、DPI、尺寸、操作方式、截图：
project_id / run_id / revision / 输入输出 hash / 数值误差：
未验证、阻塞及下一条 Red：
```

原始日志与机器报告分别保存，不用手写 pass 摘要替代日志。失败日志按执行时间追加，不被下一次成功覆盖。更新 `doc/development_status.md` 时保留平台原 Gate 缺项；清楚区分专项通过与主平台通过。

## 7. 结束条件

专项 NED-01～14 全部必需子用例通过、真实拖放/插入/DPI/保存重开和独立数值证据齐全、最终 Debug/headless 累计回归无失败后，才交接专项完成。产品仍有已知阻断缺陷或必需证据缺失时不能结束为成功，也不能只给后续计划代替已授权代码工作。

最终交接包含：实际修改、根因、可运行应用/示例、重跑命令、测试数量和失败/未验证清单、报告位置、平台 Gate 真实状态及剩余工作。若专项完成而主 G0/G1 仍缺原验收项，应明确报告，不把缺项自动改成可选。

## 8. 启动提示词

> 在当前 audioalgo 仓库直接实施节点交互修复。先读 AGENTS.md 指定的三份主文档，再读 doc/plan_editor_node_interaction.md、doc/testing_editor_node_interaction.md、doc/agent_loop_editor_node_interaction.md 和最新 doc/development_status.md，检查真实源码、工具、测试 inventory 和历史证据，重建建立基线，然后按 NI0000～NI0006 连续开发：修复文字叠字并保持 UTF-8 正确，建立编辑命令与编辑/运行分层校验，修复放置避让、顶层命中及 Output 选择，实现描述驱动的节点库拖到画布、端口拖线/断线、连线命中和原子插入、相关拓扑撤销重做，完成保存重开与 GUI/CLI 独立数值验证。每次只推进一个可验收行为，严格执行 Define→Red→最小实现→Green→Refactor→累计回归→证据记录；先确认失败原因再修复，不放宽阈值、不删断言、不跳过必需测试、不伪造桌面证据，不以旧二进制或旧 pass 替代当前验证。NED-01～14 所有必需子用例、真实桌面拖放/插入及 100/150/200% DPI 证据齐全后才声明专项完成。维护 doc/development_status.md、build/reports/loops/NIxxxx/ 和专项汇总报告；同一根因三次无进展就缩小重现、核对锁定上游接口、记录设计调整后继续。常规决策和阶段推进无需向我确认，遵守实际工具权限，不自动提交/推送/发布，不覆盖用户音频；外部限制如实记录并继续不受影响的工作。专项完成不代表 G0～G6 平台全部完成，最终报告真实结果、命令、证据和剩余验收项。
