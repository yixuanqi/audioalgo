# 【1024Builder作品秀】AudioAlgo Lab——音频算法可视化实验平台

## 作品介绍

AudioAlgo Lab 是一个用 TRAE 从想法打磨成可运行作品的音频算法研发平台：像画流程图一样搭音频处理链，调参、试听、验证，一步到位。

**核心闭环（全部真实实现，见图1–图3）**：

- **节点画布**：从节点库拖入 File Source / Gain / Mixer / Output / Channel Swap，连线搭建处理图，支持拖拽、连线、插入、删除、Undo/Redo
- **参数实时调整**：Inspector 表单带类型校验、范围与单位（图2：Mixer 主/副通道独立 dB 滑块），非法值会被拒绝并定位到具体参数
- **一键 Run**：离线渲染整张图，状态栏显示 run id、帧数和**确定性 SHA-256**（图3）——同一工程重跑、甚至换命令行跑，结果逐字节一致
- **波形显示 + 真实声卡试听**：渲染完成后直接 Play 输出
- **CLI 与编辑器共用同一引擎**：命令行跑同一工程，输出 SHA 与 GUI 完全一致（图3 中的 `aee80dff…` 与 CLI 运行完全相同）
- **独立数值验证**：Python oracle 逐样本比对。双源混音输出与公式 `10^(p/20)·A + 10^(s/20)·B` 的最大误差 **2.94e-08**

**技术底座**：C++20 + JUCE 8.0.7。算法层零 GUI 依赖，节点通过描述符+工厂注册——画布和调度器里没有任何算法分支，新增算法不改框架。工程质量由 **242 项 CTest 用例**守护（Debug 全量 242/242 通过）。

## TRAE 在创作中发挥的作用

- **架构设计伙伴**：从模块分层（算法核心 / 节点 SDK / 工程模型 / JUCE 执行投影）到依赖约束，TRAE 协助完成并持续审查边界——例如"应用层不依赖 JUCE""画布零算法分支"都有自动守卫测试
- **TDD 循环引擎**：每个行为先写失败测试（Red）→ 最小实现（Green）→ 回归，全程留有可溯源的证据链。从单个 Gain 节点到双独立源 Mixer、命名端口、按端口反向裁剪，TRAE 驱动了数十个完整开发循环
- **验证自动化**：oracle 逐样本比对脚本、CTest 清单、验收映射由 TRAE 编写执行，让"音频结果正确"是 1e-8 量级的量化结论，而不是"听起来对了"
- **演示打磨**：本帖的演示工程生成、独立校验脚本、截图自动化均由 TRAE 完成并实测通过
- **收口与状态管理**：开发状态、交付收口、证据 hash 绑定由 TRAE 维护，作品里每一句"已实现"都有对应记录背书
